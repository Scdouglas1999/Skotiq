# Planetarium performance benchmark harness

A deterministic, offline, headless measurement foundation for the planetarium
paint pipeline. It is the baseline an optimization loop measures against: same
fixture, same camera path, same config every run, so a change's effect on paint
time is attributable and reproducible.

## What it measures (and what it does NOT)

* **Headless benchmark = CPU rasterization time (proxy).** `flutter test` builds
  the real `SkyCanvasPainter` (+ FOV overlay), records `paint()` into an offscreen
  `PictureRecorder`, then **rasterizes the display list to a real bitmap**
  (`Picture.toImage`) and **reads the pixels back** (`Image.toByteData`) so the
  actual fill/blend/glow-blur/atlas-blit cost is included — not just the cheap
  cost of building the op list. Each frame is timed with a high-resolution
  `Stopwatch`. This uses the **software rasterizer** (no GPU under `flutter test`),
  so it is a CPU-side *proxy* for on-device GPU cost: directionally faithful for
  overdraw / fill rate / blend and, crucially, deterministic, low-noise (~1% run
  to run) and responsive to optimization. It is **not** vsync'd display FPS.
  (Earlier revisions timed only `endRecording()` — display-list *recording* — which
  finished in ~1 ms regardless of scene weight and was blind to the overdraw and
  blur passes optimization actually changes; rasterize-and-read-back fixes that.)
* **Integration test = real on-display FrameTiming.** For genuine end-to-end
  build+raster milliseconds (GPU included) on a machine with a display, run the
  integration test. This is **not** the loop's gate (it needs a display and
  varies with the host GPU); it is for manual sanity checks of real FPS.

This split is deliberate: the headless number is the reproducible optimization
signal; the integration number is the reality check.

## The stress scene

A committed, deterministic worst case (`fixtures/stress_scene.json`, ~2 MB):

* **14,000 stars** over magnitude 1.0–13.0 with a steep faint-end power-law
  distribution (most stars near the faint limit — stresses the dim-star atlas
  batch hardest) and a full B–V colour spread.
* **900 DSOs** of mixed types (galaxies, open/globular clusters, planetary/
  emission/reflection nebulae, supernova remnants) with extents 0.5–60 arcmin so
  both the point and ellipse glyph branches run.
* **18 constellation line figures** (158 segments) + constellation art + labels.
* **2,448 Milky Way band points** (144×21 galactic grid).
* **All coordinate grids** (equatorial + alt/az), ecliptic, galactic plane,
  meridian, horizon, ground plane, Sun, Moon, 4 planets.
* **Planning overlays on**: the twilight (dusk/dawn) band gauge, drawn every
  frame from the observer site + time by the accurate body-aware astronomy —
  the session-planning render path a user composes a night against.
* **FOV preset**: a rotated camera sensor rectangle + Telrad rings + an eyepiece
  circle (`FOVOverlayPainter`), exercising every FOV glyph branch.
* Observer 40°N 75°W, base time 2026-01-15T06:00:00Z.

The scene is generated by a seeded RNG (`fixture_generator.dart`, fixed seed
`0x5EED5301`) — no clock, no network, no live catalog — so regeneration is
byte-identical. The benchmark **loads** the committed JSON; it never regenerates
at run time.

## The camera timeline

`camera_timeline.dart` defines a fixed keyframe path sampled into **180 frames**:
wide start → pan across the field → deep zoom-in → hold while simulated time
advances ~30 min → zoom back out → pan home. FOV is interpolated geometrically;
position/time with a cosine ease. Simulated time is a fixed second-offset from
the fixture base time — **no wall clock is read for any timing input**, so frames
are reproducible.

## Run commands (Windows / PowerShell)

From `packages/skotiq_planetarium`:

```powershell
# Headless paint benchmark — writes benchmark/results/latest.json
flutter test test/benchmark/paint_benchmark_test.dart

# Golden gate (compare mode, default) — the anti-cheat check
flutter test test/benchmark/golden_compare_test.dart

# Refresh the golden baselines (only when an intended visual change lands)
$env:BENCHMARK_GOLDEN_MODE="capture"; flutter test test/benchmark/golden_compare_test.dart; Remove-Item Env:\BENCHMARK_GOLDEN_MODE

# Regenerate the fixture (only when intentionally changing the stress scene)
dart run benchmark/tools/generate_fixture.dart

# Real on-display FrameTiming (manual, needs a display/device)
flutter test integration_test/frame_timing_test.dart -d windows
```

## Results JSON schema

`benchmark/results/latest.json` (gitignored — a fresh artifact each run):

```json
{
  "p50Ms":  0.0,   // median per-frame CPU rasterize+readback time (ms)
  "p95Ms":  0.0,   // 95th percentile
  "p99Ms":  0.0,   // 99th percentile
  "avgFps": 0.0,   // 1000 / meanMs (CPU-raster-bound ceiling, NOT display FPS)
  "rssMb":  0.0,   // peak ProcessInfo.currentRss during the run (MB)
  "objectsDrawn": 0, // catalog objects on-screen at the densest frame (proxy)
  "frames": 180,   // number of timed frames (warm-up excluded)
  "scene":  "…",   // first line of the fixture composition
  "note":   "…"    // run context (quality tier, canvas size)
}
```

The key set and order are a stable contract: the optimization loop diffs
successive `latest.json` files by these keys. `avgFps` here is the paint-bound
ceiling (1000/meanMs), not on-display FPS — see the integration test for real FPS.

## Golden / perceptual-diff gate (anti-cheat)

`golden_compare_test.dart` renders 5 checkpoint frames (wide start, mid-pan, deep
zoom, post-time-advance, wide return) to PNGs under `benchmark/goldens/` and, in
compare mode, perceptually diffs a fresh render against the committed baseline.

* **Channel tolerance = 2/255.** Per-channel deltas at or below this are treated
  as antialiasing jitter and ignored.
* **Max changed fraction = 0.2%.** The gate fails if more than 0.2% of pixels
  exceed the channel tolerance.

Rationale: a real regression — a dropped star, missing label, lost glow, or
removed line — moves far more than 0.2% of pixels and/or produces large per-
channel deltas, so it is caught. Pure AA/rounding jitter between renders stays
well under both thresholds (headless re-renders here are in fact byte-identical,
maxDelta=0). This is the anti-cheat: an "optimization" that improves timing by
silently rendering less fails the golden gate.

Baselines are committed. Refresh them only when a change is an **intended** visual
difference (review the diff first).

## Files

```
benchmark/
  fixtures/stress_scene.json   committed deterministic scene (loaded, not regenerated)
  goldens/*.png                committed baseline checkpoints
  results/                     gitignored run output (latest.json)
  src/
    stress_fixture.dart        fixture model + JSON load
    fixture_generator.dart     seeded generator (source of truth for the JSON)
    camera_timeline.dart       scripted keyframe → frame sampler
    benchmark_scene.dart       worst-case config + painter/FOV factory
    benchmark_runner.dart      timing loop, percentiles, results writer
    golden_compare.dart        checkpoint render + perceptual diff
    frame_timing_harness.dart  animated widget for the integration test
  tools/generate_fixture.dart  CLI to (re)write the fixture JSON
test/benchmark/
  paint_benchmark_test.dart    headless benchmark (writes results JSON)
  golden_compare_test.dart     golden capture/compare gate
integration_test/
  frame_timing_test.dart       real on-display FrameTiming (manual)
```
