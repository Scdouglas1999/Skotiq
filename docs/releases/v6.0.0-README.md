# Skotiq 6.0.0 (unreleased) — Make It Real / Collaborative Sky

**Skotiq 6.0.0 is the next major release and is not shipped yet.**  
**5.0.0 (Living Sky)** shipped recently. Everything in this document is the
**6.0.0 slate** — what’s coming when that release cuts — not a rehash of Living
Sky and not a “just shipped 5.0” changelog.

6.0.0 hardens the parts you trust when you walk away, and makes multi-rig
collaboration practical for clubs and shared sites. Two pillars carry the
release:

| Pillar | One-line pitch |
| --- | --- |
| **Make It Real** | Trust Skotiq with your whole night — unattended, signed, and fail-closed. |
| **Collaborative Sky** | Image the sky together: shared calibration, distributed mosaics, live co-imaging — self-hosted only. |

This is the operator-facing overview of **new work scheduled for Skotiq
6.0.0**. It covers both the committed trust/reliability pass (`25004946`) and
the large WIP working-tree surface still landing on `feature/v6-make-it-real`.
It is deliberately longer than a marketing summary: the point of 6.0.0 is the
fixes and the new remote/collaborative surface you can actually use.

### Assumes 5.0.0

6.0.0 builds on a shipped **5.0.0 (Living Sky)** baseline. Living Sky itself
(atlas, First Light, Constellation), live master/slave mirroring, automation-core
unification, S3-compatible backup, and the 5.0 security pass are documented in
[`v5.0.0-release-notes.md`](./v5.0.0-release-notes.md) — they are prerequisites,
not 6.0.0 news. The body below is **6.0.0 new work** only.

## Highlights by audience

### Operators (single rig / remote observatory)

- Headless API is **fail-closed**: privileged routes need a token unless you opt
  into `--allow-unauthenticated`. Pairing and the static dashboard stay reachable
  so a fresh appliance can still be bootstrapped.
- Fine-grained token scopes (per resource / per action) land alongside legacy
  coarse `view` / `control` / `admin` tokens.
- Windows ASCOM COM work runs on one persistent **STA worker** with a real
  message pump and headless dialog watchdog — the root fix for the headless
  connect/capture bugs that blocked unattended Windows nights.
- Signed updates with Ed25519 **anti-freeze** and **key rotation/revocation**;
  platform signing wiring for Windows Authenticode and Android keystore (secrets
  remain owner-gated — builds no-op safely when secrets are absent).
- Sequencer states and SafeRig behavior that fail cleanly instead of leaving the
  rig in an ambiguous mid-run condition.
- Weather verdicts are host-authoritative; slaves mirror fail-closed.
- Clearer split between **Plan Tonight** (you decide) and **Unattended Autopilot**
  (preview + ownership stash so autopilot does not silently clobber unsaved
  manual sequences).
- Headless daemon now **auto-connects equipment** on startup (same setting as the
  GUI) and shuts down with a **bounded, idempotent** teardown so a hung service
  cannot wedge Ctrl+C forever.
- Disk-space watchdog runs in headless without needing an interactive “Start
  watchdog” click — blocking disk events stop the sequencer.

### Clubs & multi-rig sites

- Shared calibration libraries across participating hosts (match / accept /
  publish / retract), with consent and provenance on the wire.
- Distributed mosaics with panel claim / force-release / upload / hub assemble.
- Live co-imaging sessions with join/leave, framing offsets, sub-complete,
  contribute, and longitude baton handoff.
- Collaborative Sky UI under **Plan Tonight → Discover**.
- Collaborative routes get their own auth resources (`mosaic`, `coimaging`,
  `constellation`) instead of falling through to `system`.
- Self-hosted hub only — no public Skotiq hub or default account service
  (self-hosted hub only — same model as Constellation; the temporary “default
  hub” scaffolding was deliberately dropped).

### Remote companions (mobile / second screen / web)

- Mobile trust pass: science share from the host, host path picker, server
  search/reconnect, setup gating, QR scanner permission retry, single-flight
  park/cooling/settings, session picker pagination dedupe, lifecycle hardening.
- Live collaboration viewers and session ownership for watching or assisting a
  running host.
- Web dashboard: **bearer-safe image blobs** (no token-in-URL) and
  **sequencer load-and-start**; dome sync uses the correct `enable` body key.
- Broad **remote authority / host-switch** hardening so switching hosts no
  longer leaves stale dialogs, images, or mutations aimed at the previous rig.

## Major new functionality

### Make It Real — unattended trust substrate

#### ASCOM STA worker (Windows headless keystone)

ASCOM COM objects require a single-threaded apartment. The desktop GUI provides
a Windows message pump; headless mode historically provided neither. That was
the single root cause behind several beta-gap bugs:

| Bug | Symptom (what you saw) | Mechanism |
| --- | --- | --- |
| **B1** (#5) | ASCOM connect pops a modal driver dialog and hangs forever in headless | STA + no message pump to process/dismiss the dialog |
| **B2** (#1) | Mount won't connect in headless | `CoCreateInstance` hangs/fails on a pumpless STA thread |
| **B5** (#2) | Filter-wheel set appears to succeed but is a no-op | Property-put from a non-owning thread; STA can't marshal |
| **B18** (#3) | Camera works at first, then `StartExposure` fails until reconnect | Heartbeat polled off the STA owner; failures accumulate |
| **B19** (#4) | Loaded sequence self-cancels ~1.5s after start | Level-triggered `MountTrackingLost` on a not-yet-tracking mount (6.0.0 adds lazy baseline + regression coverage on top of the earlier edge-trigger) |

**6.0.0 fix (committed in `25004946`):** one persistent STA worker thread owns
`CoInitializeEx(STA)`, runs a real message-only window pump, and executes
**every** COM op for all **10** device wrappers (camera, mount, filter wheel,
focuser, rotator, dome, switch, weather, cover calibrator, safety monitor) via
a channel. Headless dialog suppression + a separate-thread watchdog force-closes
modal windows if `CoCreateInstance` blocks.

Honesty: the `cfg(windows)` path is syntax/format-checked in CI; **real Windows
ASCOM soak remains owner-gated** before an unattended-headless support claim.

#### Fail-closed headless auth + fine-grained scopes

Earlier builds served the API **open** when no token was configured. 6.0.0 flips
that default:

- No token + no opt-in → privileged routes **401**.
- Pairing (`/api/pairing/*`), discovery (`/api/info`), and the static dashboard
  remain reachable so onboarding still works.
- Escape hatch: `--allow-unauthenticated` (serve open). LAN exposure still needs
  `--allow-unauthenticated-lan` — a deliberate two-key requirement.
- Fine-grained scopes map routes to resources (`camera`, `mount`, `sequencer`,
  `mosaic`, `coimaging`, `constellation`, `system`, …) with view/control/admin
  actions. Legacy coarse tokens still work.
- Collaborative mosaic / co-imaging / constellation routes no longer fall through
  to `system` (a fine-grained `system` grant no longer silently unlocks club
  collaboration surfaces).

See `docs/headless-secure-setup.md` for operator setup.

#### Signed OTA, anti-freeze, key rotation, platform signing

6.0.0 adds operational and hardening pieces on top of the existing fail-closed
Ed25519 updater contract:

- **Anti-freeze / anti-rollback:** vendor-signed `releaseDate` must move forward
  per channel; older or implausibly future manifests are refused. High-water
  mark advances only after a fully verified stage.
- **Corrupt watermark fail-closed:** a corrupted anti-freeze store no longer
  fail-opens into “accept anything.”
- **Key rotation / revocation** support in the verifier path.
- Release workflow wiring for update-manifest signing, **Windows Authenticode**,
  and **Android release keystore** — each **no-ops safely** when its secret is
  absent (build succeeds, artifact stays unsigned / OTA stays refuse-all).

Until real keys/certs/server are provisioned, official builds remain
manual-update / unsigned in practice. The code path is ready; evidence is still
owner-gated.

#### Headless unattended services (WIP — landing in 6.0.0)

Working-tree headless bootstrap work that completes the “walk away” story for
6.0.0:

- **Startup auto-connect** — the headless twin of the GUI
  `StartupAutoConnectLauncher`. Honors `ProfileService.autoConnectOnStartup`,
  refuses to drive a non-local backend, and **fail-softs**: a dead device or
  backend readiness failure logs loudly and leaves the API up for remote
  recovery instead of crash-looping the daemon.
- **Bounded shutdown coordinator** — SIGINT/SIGTERM safes the rig, then tears
  down mDNS / relay / HTTP / OTA / auto-save / providers with per-step timeouts.
  A second Ctrl+C forces exit; a hard deadline is the final backstop. Fixes the
  failure mode where a hung `stop()` left the daemon wedged and swallowed
  further signals (only SIGKILL worked).
- **Disk-space watchdog** — starts against the configured capture path without
  an interactive button; blocking severity stops the sequencer and logs why.

#### Plan Tonight vs Unattended Autopilot

6.0.0 makes the **operator contract** between planning and autopilot honest:

- **Plan Tonight** remains the manual / assisted planning surface.
- **Unattended Autopilot** shows a **read-only preview** of what the live
  scheduler would slew to next (same constraints/horizons as the real engine).
- When autopilot takes the editor slot, unsaved manual sequence work is
  **stashed** rather than silently discarded (`discardUnsaved: true` clobber is
  gone). Disengaging autopilot restores manual ownership and the stashed
  sequence.

#### Sequencer lifecycle honesty

Beyond B19 hardening, the executor publishes truthful mid-teardown states:

- `finalizing` — stop/cleanup in flight (busy, nonterminal).
- `stopFailed` — native stop could not be confirmed; Stop stays retryable,
  Start stays blocked.
- `cleanupFailed` — native stop confirmed but persistence/end-session failed;
  identity retained so Stop can retry cleanup without losing the run.

These replace “looks idle but isn’t” / “looks failed but Start is weird”
ambiguity after a bad stop on a remote or flaky host.

#### SafeRig depth

SafeRig (park / dome / cover / pause) gains clearer per-step ownership and
shutdown-aware behavior:

- Optional steps: abort exposure, quiesce secondary capture loop, disable cooler
  — gated so weather pauses and terminal shutdowns do the right thing.
- Idle/already-paused sequencer is not sent a spurious pause (backends that
  reject that command no longer look like safing failures).
- Already-parked / disconnected mount skips park cleanly.
- Per-step failures are keyed (`exposure`, `pause`, `park`, `dome`, `cover`,
  `cooler`, `secondaryRig`) instead of a single opaque failure.
- Terminal shutdown aborts a live exposure before parking so the mount does not
  move under an integrating sensor; weather safing can leave cooling on so a
  resumed run stays cold.

### Collaborative Sky — distributed imaging

Collaborative Sky is new in 6.0.0: coordinated multi-rig product flows (shared
calibration, distributed mosaics, live co-imaging) beyond Constellation’s async
tile contribution. **Self-hosted hub only** — Skotiq does not operate a
public default hub.

Database **schema v56** (additive) is the trust substrate:

- `calibration_tags`: `shared_by`, `shared_at`, `license`, `provenance_json`,
  `published_remote_id`
- `mosaic_panels`: `assigned_rig_id`, `assigned_user_id`, `claim_token`,
  `uploaded_master_id`
- `constellation_contributions`: `session_id`
- New `co_imaging_sessions` (+ unique `(hub_key, session_id)` index)

#### WS1 — Shared calibration libraries

**Pain killed:** re-shooting sensor-matched darks another club member already has.

Operator flows (local + headless):

- List / match remote masters against a light-frame context
- Accept (download-on-accept into the local library)
- Publish (consent-gated — private/fail-closed licenses do not publish)
- Retract
- Tag / delete with scoped auth

Flats remain optics-train specific; the matcher must refuse unsafe cross-train
flat reuse. Darks are the primary safe share (sensor + gain/offset/binning +
exposure/temp).

Headless surface includes `/api/calibration-library` and related match / accept /
publish / retract / tags routes.

#### WS2 — Distributed mosaics

**Pain killed:** a 20-panel mosaic takes weeks on one rig.

Flows:

- Publish a `MosaicProject` as collaborative work
- Join / status
- Claim a panel (baton anti-double-collect) and force-release when needed
- Upload panel masters
- Assemble + fetch output

Headless routes under `/api/mosaic/collaborative` and
`/api/mosaic/projects/<id>/…`. UI cards and remote-join flows live under the
Collaborative Sky / mosaic screens (WIP — landing in 6.0.0).

#### WS3 — Live co-imaging

**Pain killed:** a faint target needs more integration than one longitude window.

Flows:

- Create / list / get sessions
- Join / leave / close
- Contribute subs; mark sub-complete
- Framing-offset assignment so rigs don’t stack identical noise
- Baton auto / claim / release for follow-the-night handoff

Headless routes under `/api/coimaging/sessions/…`. Consent gates fail closed
(WS4).

#### WS4 — Trust, consent, provenance, scoped auth

- Publish/share paths require explicit consent / license; private defaults fail
  closed.
- Provenance fields travel with shared masters and collaborative artifacts.
- Fine-grained resources separate collaborative access from system admin.
- Rate limits cover collaborative mutating endpoints (claim, upload, contribute,
  chat/annotation-style surfaces where present).

#### WS5 — Collaborative Sky UI

Unified surface under **Plan Tonight → Discover**: active collaborative mosaics,
co-imaging sessions, shared library cards, join/consent sheets, and progress.
Without this UI the plumbing is invisible; with it, 6.0.0 reads as a product on
first launch.

### Remote / Master–Slave / authority

6.0.0’s remote work is mostly **authority correctness** — making sure UI and
providers talk to the host they think they are talking to.

- **Host switch cancels in-flight remote work** — scheduler row cleanup, planner
  candidate dialogs, quick-start discard, captured-images fetches, remote
  settings, image thumbnails, guider star images, etc. cannot land on host B
  with host A’s payload **(landing in 6.0.0)**.
- **Authority-bound dialogs** close themselves when the backend swaps so you
  cannot confirm a destructive action against the previous host
  **(landing in 6.0.0)**.
- **Slave-blind Living Sky route parity** — NetworkBackend / Constellation
  methods without a host route fail loudly in tests instead of returning empty
  local state on a tablet **(landing in 6.0.0 / parity net)**.
- **Profile default + sort order** round-trip so a slave looping status cannot
  thrash the host’s default profile **(landing in 6.0.0)**.
- **Focus-model / should-refocus** answers a slave queries match the host’s
  in-run decision **(landing in 6.0.0)**.
- **Imaging sessions, stack-and-share, science raw settings, meridian flip,
  notes, flat capture config** — remote authority tests pin host-owned truth
  **(landing in 6.0.0)**.
- **Session ownership still required for destructive mutations**; status/read
  paths stay open to viewers **(landing in 6.0.0)**.
- **Focuser command authority** — an equipment profile is connection intent, not
  live move authority while disconnected **(landing in 6.0.0)**.
- **Non-idempotent hardware POSTs remain single-attempt** (companion trust pass
  continues to rely on that contract).

## Breaking changes & migration

Upgrade carefully if you automate against the headless API or rely on previous
default-open behavior.

| Change | What to do |
| --- | --- |
| Headless without a token now **401s** privileged routes | Issue a token (`--auth-token`, `SKOTIQ_AUTH_TOKEN`, or `--require-auth` / pairing), or start with `--allow-unauthenticated` only where you deliberately accept open risk. LAN open still needs `--allow-unauthenticated-lan` as well. |
| Fine-grained collaborative resources | Tokens that only had `system` no longer silently unlock `/api/mosaic/collaborative/*`, `/api/coimaging/*`, or constellation collaborative routes — grant `mosaic` / `coimaging` / `constellation` as needed. Legacy coarse `admin`/`control` still work. |
| Dome sync body key is `enable`, not `enabled` | Update clients/scripts that POST `/api/dome/sync`. |
| Backup `customPath` is rejected; restore prefers `id` | Stop sending `customPath`; restore by backup id. |
| Sequence children route requires `parentNodeId` | Include `parentNodeId` on the children route. |
| Mock push requires `mock: true` explicitly | Set `mock: true` in the request body; omit it and mocks will not run. |
| Autopilot no longer silently overwrites unsaved manual sequences | Save or discard manual sequence edits before starting autopilot; use ownership / preview / stash flows as designed. |
| DB schema **v56** | Additive Collaborative Sky columns/tables. Back up before upgrade; migration is tested v55→v56. |
| OTA / signing | Until keys are provisioned, behavior remains refuse-all / unsigned — do not assume auto-update just because the updater binary exists. |

**Upgrade from 5.0.0:** configuration and profiles preserve across upgrade;
Living Sky tables from v52–v55 remain. Schema v56 is additive. Official public
packages may still be manual-update until OTA secrets are live.

## Known limitations / not yet proven

These are honesty constraints for the unreleased 6.0.0 train. Prefer this README
and in-app behavior when older `known-limitations.md` rows lag the code.

### Owner-gated evidence (release gate)

- Hardware soak, second-device LAN/firewall smoke, live S3/MinIO/B2 restore, and
  production signing evidence remain **owner-gated**. The public release gate is
  **not ready** until that evidence lands.
- Windows STA needs soak on **Windows with real ASCOM** hardware — not only CI
  or mock paths. Until then, treat fully-unattended **headless** acquisition on
  real ASCOM as **still being hardened**; desktop GUI path remains the supervised
  default for critical nights.
- Authenticode / Android release signing / live update server require secrets
  the open tree does not contain. Builds succeed unsigned / OTA-refuse-all when
  secrets are absent.

### Product / deployment model

- Collaborative Sky and Constellation remain **self-hosted hub only**. There is
  no Skotiq-operated public hub (default-hub scaffolding was explicitly
  dropped).
- Fine-grained tokens exist, but operators still typically issue a small set of
  view/control/admin or resource-scoped tokens — there is no full custom RBAC
  UI yet.
- Shared flats across different optical trains are intentionally refused /
  unsafe; shared darks are the primary library win.
- INDI weather/switch parity for unattended safety claims still needs
  verification on real Linux/macOS observatory stacks.

### Documentation / packaging lag (6.0.0 in progress)

- Formal `version.yaml` may still read **5.0.0** until the release train cut;
  treat **6.0.0** as the intended product label for this work.
- A dedicated CHANGELOG 6.0.0 entry may not be published yet; this README is the
  operator-facing overview until that lands.
- Some docs under `docs/known-limitations.md` still describe pre-6.0 accepted
  limitations (e.g. open headless, manual-update-only). Where 6.0.0 code has
  flipped the default (fail-closed auth, anti-freeze, STA worker), **prefer this
  README**.

Living Sky breadth and other shipped 5.0.0 behavior are prerequisites — see
**Assumes 5.0.0** above and [`v5.0.0-release-notes.md`](./v5.0.0-release-notes.md).
Do not treat those as new 6.0.0 bugs or features.
