# Skotiq 3.1.0 — Full-Night Readiness

This is a major reliability and capability release with one goal: letting an advanced
rig run a **full, unattended deep-sky night** end to end — and exceeding competing
software while doing it. It lands a complete four-wave audit remediation of the imaging
workflow, a round of competitor-exceeding features, an architecture-unification pass,
and a full design-system migration, plus a batch of user-reported UI/UX fixes.

## Unattended-night safety & reliability

- **Safe-state on abort/park** — end-of-night and emergency park now close the cover
  **and** dome and bring the rig to a genuine safe state, not just stop the mount.
- **Disconnect → reconnect → resume** — a device dropping mid-sequence now recovers:
  reconnect, re-acquire the guide star, and retry the interrupted instruction instead
  of silently stalling the night.
- **No idle-for-the-night / no single-target loop** — frame attribution records the real
  `target_id` and exposure length, so the scheduler re-dispatches on natural sequence
  completion and per-target/filter integration time is tracked correctly.
- **No daylight imaging** — the live scheduler gates on twilight / Sun altitude and
  parks the mount at dawn via a distinct end-of-night hook.
- **Weather-unsafe & low-disk enforcement** — computed safety actions (pause + park +
  close) are actually executed; the Rust executor now consumes the Dart weather-safety
  verdict as defense-in-depth (OR-of-unsafe, fail-closed).
- **Single weather-verdict authority** — eliminated the double-evaluated verdict and
  closed the abstain landmine (abstain is now a real `None` channel, not a silent
  `false`), so "unknown" never reads as "safe".

## Scheduling & autopilot

- **Planner is now a read-only preview of the live autopilot** — the three former
  target-selectors are unified into one engine; what you see in the planner is exactly
  what the scheduler will do.
- **Per-azimuth horizon mask** — the runnable gate *and* `AltitudeAbove/Below` loop
  conditions honour a real per-azimuth horizon profile, not one flat altitude.
- **Count-based completion** — filter budgets can target a frame **count**, not just
  time, so plans finish when the data is actually in hand.

## Guiding, focus & centering

- PHD2 dither waits for a real settle (and fails closed on a failed settle).
- Polar-alignment error reported in arcsec with corrected, non-collapsing geometry.
- Autofocus temperature-compensation **sign clash fixed** and predictive autofocus wired
  through the Dart paths.
- Slew-and-center now converges — solved RA is correctly converted from degrees to hours.
- Guiding screen: restored the far-right toolbar buttons, Brain-parameter load now shows
  an error + retry instead of failing silently, and the guide-graph uses a sensible
  time X-axis.

## Image acquisition & quality

- **Per-sub eccentricity** — computed from real star-shape moments in the native
  detector, used to fire the eccentricity grade gate, and surfaced as a color-graded
  cockpit overlay (was previously a gate that could never fire).
- **Live stacking auto-feed** — accepted frames now feed the live stack during sequencer
  runs (first accepted frame = reference, stack grows, broadcast over LAN). The node
  existed before but was never fed in production.
- **Analytics from real metrics** — sub grading uses real eccentricity / FWHM, and
  rejected subs are excluded from project integration totals.
- **Smart Night** — ADU-targeted flats, temperature-matched darks, a live guide-RMS
  ceiling, and no more silent pixel-size assumptions.

## Plate solving

- RA unified to degrees across every solve path.
- Local **ASTAP fallback** made functional and fail-loud (no more swallowed
  `PLTSOLVD=F`), honouring the configured solver path and catalog flags; clearer
  ASTAP-catalog messaging.
- Solve feedback + comprehensive plate-solver settings with UI polish.

## Weather & cloud-motion

- **Real per-cell radar data** drives cloud-motion prediction (RainViewer / NOAA / GOES
  decoded into a spatial intensity grid), replacing the uniform-field placeholder.
- Cloud-motion analyzer computes genuine per-cell density + motion/ETA, and surfaces an
  honest **"unavailable: &lt;reason&gt;"** in the run dashboard instead of fabricating
  motion when inputs aren't present.

## Live monitoring cockpit & dashboard

- NINA-style live cockpit of customizable tiles: dome / cover / switch telemetry +
  Observatory tile, raw weather conditions, live HFR / FWHM / star count with sparklines,
  scale-aware grading, and honest per-filter integration.
- **Live-frame card redesign** — action buttons + pan, thumbnail history, and a fixed
  filter selector.
- Image display restored, sequencer header overlap fixed, tabs consolidated, and a
  slimmer bottom status banner.

## Mobile companion & remote control

- **Remote parity** for the full unattended-night knob set (autofocus / dither /
  recovery / weather-park, calibration, dark-library, pre-flight, Smart Night, site,
  meridian, plate-solver, and the long tail), with a fail-loud guard on the residual.
- Device-class detection uses the **shortest screen side** on mobile OSes, so foldables
  (e.g. Z Fold cover screen) classify and lay out correctly in landscape.

## Settings, equipment & data safety

- Backup/restore **data-loss guard** — validate before clear, plus location-(0,0) unset
  detection and broader remote-settings coverage with fail-loud guards.
- Equipment: de-duplicated the two competing reconnect engines and added a clear
  "reconnecting" UI state.

## Design system & UI consistency

- Full **design-token migration** across every screen cluster (sequencer, imaging,
  planetarium, settings/equipment, analytics/dashboard, planner/scheduler, misc):
  hardcoded radii / font sizes / raw colors → `skotiq_ui` tokens.
- New **SkotiqIcons** semantic icon set; inline `TextStyle`s folded to named
  typography roles.
- **SkotiqCard / SectionWell / ScreenHeader** component adoption across hand-rolled
  card surfaces.
- Raw named colors routed through the semantic / data-series palette for correct
  **red-night mode** rendering, with an `audit:design-tokens` regression guardrail.

## Under the hood / quality

- **Notification system unified** to one `NotificationRouter` producer with a single
  shared event→category classifier (exactly-once delivery).
- **Device/disconnect simulation harness** for unattended-night safety + recovery, and a
  **golden-screenshot harness** pinning the design language.
- Reduced PHD2 log spam; camera "Exposing" status now shown in the sequencer; removed
  internal/scratch files from the public tree.

## ⚠️ Hardware-validation note

The hardware-touching fixes (rotator move-and-verify, polar alt/az split, disconnect→
resume cycle, live PHD2 dither settle, focuser temp-comp sign + predictive autofocus,
and the weather/disk park + dome/cover physical-close path) are **implemented and
unit-tested**, and the core path has been validated on a real imaging rig — but the
dome/cover/observatory paths are still being shaken out by the tester group. If you run
fully unattended on expensive equipment, supervise the first night and confirm your park
/ safety behaviour before trusting it lights-out.

## Install

- **Windows** — run `Skotiq-3.1.0-Windows-Setup.exe` (bundles all camera/mount
  vendor SDK runtimes).
- **Linux (x64)** — extract `Skotiq-3.1.0-Linux-x64.tar.gz` and run the bundled
  binary. Requires GTK3 / libsecret / libraw runtime libraries.
- **Android** — install `Skotiq-3.1.0-Android.apk` (the remote-monitoring & control
  companion; pair it to a desktop host on your LAN).
