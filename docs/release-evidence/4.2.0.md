# Release Evidence — 4.2.0

This document records what was actually exercised for the 4.2.0 release, and at
what level. It exists so claims in the README and release notes can be traced to
real testing rather than to code presence. **A vendor name or capability in the
codebase is not a support guarantee** — only rows marked *real hardware tested*
were run against a physical rig.

Evidence levels, from weakest to strongest:

- **Code implemented** — written and compiles/analyzes clean, no runtime check.
- **Unit tested** — covered by an automated `flutter test` / `cargo test` case.
- **Simulator tested** — exercised against a simulated device or generated input.
- **Real hardware tested** — run against the physical device named below.
- **Not yet validated** — in scope but not exercised at any level above.

## What 4.2.0 is

4.2.0 is a large sequencer + architecture hardening release. The headline work:

- **Sequencer correctness** — progress/ETA are now loop- and SmartExposure-aware
  (the bar no longer maxes out early inside loops); the duration estimate, the
  per-node chip and the run-dashboard total share one overhead model; the
  executor rolls back cleanly on a failed start (no "ghost running" state).
- **Sequencer UX** — mouse/touch tree collapse, drag-reparent cycle guard,
  snippets insert enabled, run-dashboard skip-target, glance mode, an app-wide
  running-sequence mini-player, library tags/favorites/version-history, real
  diff-vs-previous-run, multi-filter mosaics.
- **Typed photometry events** — promoted from stringified detail to first-class
  typed `SequencerEvent` variants (Rust + flutter_rust_bridge), following the
  existing Wave-3 typed-payload precedent; the light-curve panel binds typed
  fields instead of parsing strings.
- **Architecture** — a new `audit:bridge-boundary` enforces that only
  `skotiq_core`/`skotiq_bridge` import the Rust bridge; the real UI
  leaks were relocated behind `ImagingBackend`/`GuidingBackend`/`DeviceBackend`
  role seams (FFI + network + disconnected impls). Whitelist is legit-only (13).
- **Schema v49** — additive migration adding per-run sequence snapshots,
  sequence tags/favorites, a `sequence_versions` table, and per-session
  diagnostics persistence.

## Evidence level of the 4.2.0 delta

The 4.2.0 changes are verified at **code-implemented + unit/widget-tested +
(where applicable) simulator-tested** level. They were **not** re-run against a
physical rig beyond the 4.1.0 hardware baseline. In particular:

| Area | Level |
| --- | --- |
| Sequencer build/edit/run UI + correctness fixes | Unit/widget tested |
| Schema v49 migration | Synthetic migration regression tested (passes); **not** verified against a real older user database |
| Typed photometry events | `cargo check` + analyze; emitted alongside legacy events (back-compat); not run on a real photometry session |
| Bridge-boundary relocations (incl. dome/cover over network) | Unit tested + analyze; network impls not re-run on a real second device |
| Multi-filter mosaic, versioning, tags | Unit tested |

## Outstanding conservative-gate blockers (carried, user-only)

`audit:public-release-gate` reports **NOT_READY** with 5 blockers, all requiring
real-world evidence the build host cannot self-produce (identical class to the
items carried at 4.0/4.1):

1. **Full hardware/control smoke** — real/simulator dome, weather, safetyMonitor.
2. **Older real profile/database migration** — a real pre-4.2 database artifact
   to confirm the v49 migration end-to-end (synthetic coverage passes).
3. **Second-device LAN/firewall smoke** — a second physical device through the
   real router/firewall path.
4. **Real remote-control actions** — real/simulator device action evidence.
5. **Final release checklist/sign-off** — depends on the above.

These are advisory (not hard CI gates). They are tracked for the owner to close
on a physical rig; the README and known-limitations docs already scope public
claims to the verified Windows path.
