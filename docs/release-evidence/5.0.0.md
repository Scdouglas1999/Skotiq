# Release Evidence — 5.0.0

This record separates automated/non-hardware verification from checks that
still require a physical rig, second device, or release-owner sign-off. It
applies to Skotiq `5.0.0+23`; official artifacts record their exact source
SHA in `SOURCE-COMMIT.txt`.

## Current decision

**Non-hardware release engineering: passed. Public unattended-hardware sign-off:
pending.** The conservative public-release gate passes 21 checks and retains
four blockers: full hardware/control smoke, second-device LAN/firewall smoke,
real remote-control actions, and final sign-off after those checks. These are
not papered over or converted into proxy evidence.

## Artifact and dependency scope

- Linux and Windows archives include the Skotiq license, third-party
  notices, LGPL-2.1 text, and source commit provenance.
- LibRaw remains dynamically linked and bundled. Unix `rusb` now dynamically
  links system libusb instead of statically vendoring LGPL code; the built
  bridge records `libusb-1.0.so.0` as a shared `NEEDED` dependency.
- Official artifacts do not redistribute vendor device SDK binaries. The
  Windows staging script requires an explicit local-only opt-in, while the
  release workflow rejects known SDK DLLs.
- Official 5.0.0 artifacts are manual-update-only. The package contains no
  updater executable, trusted update public key, or configured update server.
- Windows is an unsigned portable beta. Android is a debug-signed sideload
  beta. No macOS artifact is shipped.

## Claims constrained by implementation

- First Light can submit confirmed detections to the TNS bot API. AAVSO and MPC
  are manual file exports, not network submission.
- Constellation uses an operator-run, self-hosted hub URL. Skotiq provides
  no hosted public/default hub in 5.0.
- Desktop master/slave mode is covered by wire-contract, parity, and local-stack
  tests; it is not yet claimed as a completed two-physical-machine LAN soak.
- S3 backup is tested against an in-process object store; operators should test
  their own S3/MinIO/B2 endpoint and a disposable restore.

## Physical/external checks still required before publication

1. Run the hardware/control smoke on the intended Windows rig, including safe
   commands and read-back for every applicable device class.
2. Reach the packaged host from a second physical device through the real LAN
   firewall/router path; verify dashboard assets, auth rejection/success,
   WebSocket connection, and reconnect.
3. Exercise safe remote-control actions and preserve the server audit log.
4. Complete final owner sign-off against those artifacts and the known
   limitations.

Until then, supervised beta use is the truthful scope; unattended or fully
verified hardware claims remain blocked.
