# Skotiq 4.1.0

4.0 was the big "run your rig from the couch" release. 4.1 is the follow-up that
makes the whole thing feel solid: the catalog experience got rebuilt, the remote
and appliance paths got sturdier, there's a new real-time insight feed and a new
weather source, and a long tail of crashes, races, and rough edges got fixed.

## What's verified — first public beta

Skotiq is verified on **Windows**, where the desktop app drives ASCOM/Alpaca
cameras, focuser, filter wheel, and PHD2, with plate-solving and planning. Remote
**monitoring and planning** over the LAN — from the web dashboard and the Android
companion — are verified. Fully-unattended **headless** acquisition on real ASCOM
hardware is **still being hardened** and should be supervised. **Linux** is in
early testing; **macOS** builds in CI with no hardware soak. Every other device
path is **capability-gated** — present in the app but not a support guarantee
until verified per rig. The honest, level-by-level record of what was run on real
hardware is in [`release-evidence/4.1.0.md`](../release-evidence/4.1.0.md).
Supervise your first nights.

## Catalogs that just work

Catalog downloading and management was the roughest corner of 4.0. It got a
ground-up overhaul:

- **Your installed catalog is never at risk.** Downloads stage to a temporary
  file and only swap into place once they're complete and verified. Before,
  pressing Download immediately truncated your working catalog — so a dropped
  connection could leave you with a broken one that still reported "Installed,"
  and it never self-corrected.
- **You can cancel.** Any download can be stopped mid-flight, including the
  multi-gigabyte GLADE+ galaxy catalog — which now streams straight to disk
  instead of buffering the whole file in RAM (and counts its objects by
  streaming too, instead of loading the entire catalog to count lines).
- **Progress survives navigation.** Leave the screen and come back and the
  download is still running, still showing progress, instead of looking idle.
  Download state now lives in the catalog manager, not the screen widget.
- **The cards actually tell you something.** Each catalog shows its on-disk
  size, version, object count, magnitude depth, and what it's for (plate solving
  vs. planetarium display vs. image annotation), plus an "update available"
  hint when your installed version is behind.
- **The planner stopped lying.** A bug where the planner's empty-state insisted
  your deep-sky catalog wasn't installed — even when it was — is fixed; the
  shared catalog state now stays in sync with what's actually on disk.

## Night Narrator

A new real-time insight feed (schema v48): a running, plain-language commentary
on your session — what just happened, what's drifting, what needs attention —
surfaced across the relevant screens instead of buried in logs.

## Remote, mobile & appliance

The couch-to-rig path from 4.0 got more dependable:

- **Discovery & pairing.** More reliable mDNS discovery and pairing between the
  app and a headless rig, with hardening across the discovery, enhanced-discovery,
  and remote-pairing layers — so tablets and phones find and connect to the
  appliance more consistently on the local network.
- **Appliance packaging.** Updated Avahi service advertisement and the systemd
  install path for the dedicated-box (Pi / mini-PC) setup.
- **Mobile.** Saved-servers handling and the mobile pairing/connection paths got
  cleaned up so reconnecting to a known rig is smoother.

## Headless API — parity & hardening

The REST/WebSocket surface that powers remote control moved closer to
feature-parity with the desktop and got safer:

- More desktop-parity endpoints (defect mapping, post-session operations,
  live-stacking and session-science operations, sequencer and planetarium
  handlers).
- **Fails closed on unknown auth scopes** instead of allowing them.
- **`/api/info` now advertises every registered route** (15 were previously
  missing).
- **Handler errors are logged explicitly** instead of being silently swallowed,
  and request validation was tightened.

## Autopilot & sequencer

Continued hardening of the unattended-autopilot internals — refinements across
the autofocus, exposure, meridian-flip, and fault-recovery paths in the native
sequencer, plus a guard so live stacking can't start before the native layer is
initialized.

## Weather & location

- **Met.no cloud-cover provider** with radar failover and transient-HTTP retry,
  so the forecast and cloud read degrade gracefully instead of going blank on a
  flaky connection.
- **First-run location auto-detect** by IP, so the planner and twilight math are
  sensible before you've entered coordinates.

## Reliability, correctness & tooling

- **Typed exceptions** on the imaging and backend service boundaries, so
  failures carry structured context instead of opaque strings.
- **Crashes fixed:** a trigger-dialog footer that crashed (an `Expanded` inside
  a `Wrap`), and a frame-persistence race against container disposal.
- **Linux desktop is now self-contained.** The bundle ships and loads its own
  libraw and sqlite (bridge `RUNPATH=$ORIGIN` plus a `./skotiq` launcher),
  fixing a startup crash on rolling-release distros whose system sqlite ABI
  differed from the build's, and a case where the native bridge couldn't find
  bundled libraw at all.
- **Autofocus settings layout fixed.** The merged Autofocus / Predictive
  Autofocus settings page no longer splits into two half-height, independently
  scrolling panes — it's one continuous scroll.
- **Planetarium:** the deep-star tileset now defaults to empty cleanly and
  best-effort failures are logged rather than thrown.
- **64 new native protocol tests** (PHD2, INDI, Alpaca, rolling RMS) and
  expanded schema-v48 migration / narrator-event coverage.
- **Rust workspace:** a clean clippy gate, documented-unsafe blocks, and
  cargo-fmt across the native crates.
- **Analyzer sweep:** production analyzer infos cut from ~485 to ~60, dependency
  constraints aligned across the workspace, and generated (freezed/mockito)
  outputs regenerated for the Flutter 3.44 toolchain.
- **CI/release:** several long-broken gates fixed (coverage, restored gate
  inputs, baseline comparisons) so the release gate actually runs end to end,
  and the Linux release now builds against glibc 2.35 so the bundle boots on the
  Bookworm/Raspberry Pi appliance.

The full itemized list is in `../CHANGELOG.md`.

The Android APK is debug-signed — fine for sideloading, but not a Play Store
build. As with 4.0, if a future release switches to a real signing key you'll
have to uninstall and reinstall rather than update in place.

## Carried over from 4.0

The on-sky caveat still stands: the finishing and photometry algorithms are
tested against synthetic data and are internally consistent, but their accuracy
hasn't been validated against real frames. If you submit measurements anywhere,
shoot a field with published comparison-star magnitudes first and confirm the
numbers land where they should. iOS and live cellular-push delivery still need a
Mac/Apple Developer account and your own Firebase/APNs keys, respectively.
