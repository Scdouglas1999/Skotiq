# Skotiq 9.4.0

Update the imaging host to 9.4.0 first, then update each linked desktop or mobile client. Skotiq requires both ends of a Link connection to run the same release. The desktop and companion apps are build 47.

Most of this release is internal cleanup: code that was written two or three times now lives in one place, so a fix lands everywhere at once. The changes you can see are below.

## Runs and manual actions

- While a manual action (autofocus, centering, a loop) holds a run paused, only that action's own end resumes or skips the run. Before, a Resume or Skip from the web dashboard, run-watch, Home Assistant, voice control or a second linked client went through, and the run and the action fought over the camera. These are now refused with a plain message. Stop always works.
- When the action ends and something else paused the run in the meantime (weather, a device, your own Pause), the run stays paused and the app names the reason. Before, a finished autofocus could resume a run that weather had paused.
- If the linked client running the action disconnects, the run stays paused.
- Skip is no longer offered anywhere while an action holds the run.
- The command palette's Start and Stop follow the Sequencer's own run controls, so it no longer offers Start while a run is stopping or during a meridian flip.
- The Sequencer header's Preflight only looks: it can no longer unpark the mount.
- A run that fails now stops the guiding it started, as a stopped run does.
- A pause no longer shows a trigger note (such as "Filter Change fired") as its reason.
- A manual action also holds a run you had already paused, so a Resume can no longer start the run's exposure in the middle of a centering. The run stays paused when the action ends.
- When you or a manual action stop the guider, the run no longer reports a lost guide star or sends that notice.
- Starting a restored run on a restarted host no longer reports lost tracking or a lost star before the run has unparked, and its recovery no longer turns tracking on for a parked mount. The red recovery banner clears when recovery ends.
- Guiding refuses to start while the mount is parked.
- A Skip that would end the night (warm the camera and park) asks first.

## Times

- Times in the Sequencer's step list (including folded runs), Smart Night's window, Tonight's end-of-night deadline and the whole Plan screen now use the site's clock, like the rest of the app. Before, some showed the computer's time zone next to site times.
- The Planner picks the right night when the site's time zone differs from the computer's.

## Phone

- The connection, first-run and error screens follow your Language and Font size settings.
- On a phone turned sideways, the connection screens use the phone layout, and the Sequencer keeps room for the plan.
- First-run setup can create a new capture folder on the host, as Settings already could.
- The Templates and Saved tabs show the live run's controls.
- The Live Activity and ongoing notification read centering and exposure steps by what they are doing, not by their name. The ongoing notification is one line, names the filter and frame count, and says when a manual action holds the run.
- The ongoing notification comes back when the app restarts during a run.
- The app no longer takes the Wi-Fi lock every couple of seconds during a run (about 600 times in 15 minutes before).
- A short Wi-Fi drop keeps the "reconnecting" banner over the screen you are on, instead of showing the connect screen.
- Resume and Skip are greyed out on every screen while a manual action holds the run; the small run bar says what holds it.
- Language is set per device, like text size. Before, changing it on the phone changed the host's language too.
- A linked phone can set the host's Sequences folder and choose which events the host pushes (pairing with full control only), and is pointed to where it sets Discord, Pushover, Home Assistant and backups.
- On a sideways phone, steps are added from the plan's last line, so nothing covers the ETA column.
- After a restore, Tonight's plan bars and time count the frames the run already has.
- History offers "Continue run" only on the run that can continue; its autofocus count reads "Autofocus succeeded".
- Device notices (such as a switch failure) reach the phone; before, it dropped them.

## Notices

- Switch failures, PHD2 starting and a late exposure go through Settings › Notifications like other notices: their rows can turn them off.
- The guiding card says "Not guiding" once.
- The Plan screen's integration goals read the filter wheel's own filter names. Before, it could say the wheel had no slots.
- Chart axes no longer repeat the same label.
- "Waiting for the flip" clears when the flip ends.
- Recovery progress reads "2nd of 3", not "2th of 3".
- Adaptive exposure warnings show sub-second limits correctly.
- At exactly 0.5 °C from the setpoint, every screen now agrees the camera is still cooling.

## Sync, sharing and plugins

- S3 and WebDAV sync, the hub and shared calibration give up only when no data has moved for a while, instead of after a fixed time. A stalled S3 endpoint no longer leaves "A push is already in progress" until restart, and large uploads on a slow link finish.
- A calibration master the hub refuses reaches a linked client as a refusal, not as "hub unreachable". Hub conflicts (such as a handoff another rig holds) are no longer described as a tile mismatch.
- A raw frame the hub refuses is counted as rejected.
- Plugin settings live under the app's data folder. Existing plugin settings are copied over the first time each plugin starts.
- The Pushover, Discord and Home Assistant plugins give up after 30 seconds. A Home Assistant that takes longer now fails its step.

## Settings and backups

- The plate-solver choice has one store. Restoring a backup now applies its plate-solver settings (a bug made restores skip them), including program paths from another computer.
- A backup taken while the solver's settings can't be read leaves them out, so restoring it doesn't reset the solver.
- On a desktop started for a remote host but not linked yet, the pages that edit the host (alert destinations, Home Assistant, Integrations, push, storage paths) refuse edits instead of saving them where nothing reads them.
- Every linked client asks about a run to recover when its link comes back. The prompt only restores the run; it never starts it.

## Not tested

None of this has run on the rig. It was checked by tests and by simulated nights on this release and 9.3.5 compared side by side, at desktop and phone widths, and by driving the Android app on an emulator against a simulated host.
