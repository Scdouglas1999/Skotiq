# Skotiq 7.0.0 — Darkroom

## Summary

Wake up to a finished image you can still change your mind about.

7.0 processes your night for you and never takes anything away from you to do
it. When a sequence completes, the dawn autopilot calibrates, registers and
integrates your accepted frames into per-filter linear master lights, composes
a first-draft **recipe**, renders a draft JPEG, and delivers everything wherever
you want to work in the morning.

The draft is not a baked file. It is a *recipe* — an ordered, editable stack of
operations stored as data. Open it in the new **Darkroom** and every step the
autopilot took is there to adjust, reorder, disable or discard. "Reset to
linear" always exists and never destroys anything.

Everything below was proven against simulators on Linux. On-sky validation is
owed, and so is every Windows and Android runtime claim — see **Known
limitations**.

## The Darkroom

- **Step cards that keep three truths separate**: what the recipe says, what
  validation says, and what the render actually did — including *why* a step was
  skipped. No photometric catalog on a fresh install is an explanation printed
  on the card, not a silent no-op.
- **Branching.** Duplicate any recipe as a variant at the shared prefix, then
  compare branches side-by-side or blinking with a shared zoom and pan.
  Autopilot drafts and your own recipes are marked by author.
- **Export at any stage** — the linear master, the image after step N, or the
  final render. FITS always carries the full recipe as provenance (HISTORY cards
  plus a `.skrecipe` sidecar). A raster export of a still-linear stage is a
  visible screen-transfer choice, never a silent auto-stretch.
- **Undo and redo** over your edits. Renders are cancelled, not queued, when you
  keep dragging a slider.
- **A recipe from a newer build is no longer a dead end.** One carrying an
  operation this build cannot run renders around it, says so per step, and
  offers removal with undo.

## The dawn autopilot

When a sequence reaches its natural end, the autopilot integrates the night into
per-filter linear masters and drafts a recipe over them: gradient removal,
denoise, colour calibration where the data supports it, an auto-fitted stretch
and an edge crop. It renders the draft, writes the sidecar, delivers the set and
notifies you.

## Honest calibration, honest colour

- **Every master states exactly which darks, flats and bias frames were
  applied**, per slot, with match quality and staleness — in the result, in the
  FITS HISTORY, and in a `CALWARN` card. A missing master is an explicit entry.
  Agreeing on nothing is not a match.
- **Colour calibration is labelled for what it is**: a Johnson B−V regression
  against the shipped catalogs. It is not SPCC and is never called that. It
  refuses mono input loudly, and the dawn draft pins the fitted channel scales so
  previews render colour-correct at any zoom level.
- **Unknown gain and offset are matched as unknown** — scored and reported
  UNVERIFIED, never compared as a fabricated zero.

## Delivery

- **Targets**: any watched folder, NAS mounts included; SFTP with key auth
  through the system OpenSSH; or a paired desktop that pulls — the rig publishes
  a signed manifest and your home machine fetches it with resumable downloads.
- **Copy, never move.** Atomic writes, checksum verification, and bounded
  retries that survive a rig reboot.
- **A journal whose every status line derives from a recorded fact.** There is no
  "configured" state that has not proven itself.
- **Delivered filenames carry a rig identity**, so two Skotiqs sharing one
  drop folder cannot collide.

## Also in 7.0

- **The behavioural audit register is at zero open findings** for the first
  time. Every silent-behaviour site in the codebase was either fixed — around 65
  real defects, including vendor drivers that fabricated capabilities and safing
  paths that failed silently — or documented with the specific mechanism that
  makes it safe.
- **Your observing site is explicitly unknown until you set one.** No fabricated
  default locations anywhere; the backend is told null rather than 0/0/0.
  Simulation mode's dead toggle is gone.
- **A finished node says so.** `NodeCompleted` now answers every `NodeStarted`,
  so spinners stop when the run does.
- **A failed run no longer costs a third of a core.** Every 1 Hz clock is aligned
  to the epoch-second boundary — the idle frame rate was the number of clock
  phases, not the clock rate — and an urgent status dot pulses for twenty seconds
  and then holds.
- **A three-frame dark run reports three frames.** Calibration frames count
  toward the session report instead of showing 0/0 frames and 100% downtime, and
  the run leaves the mount parked.
- **Meridian handling reads the target's sky**, not the mount's pointing. A
  parked or non-tracking mount does not arm the flip, and preflight warns when a
  flip would re-centre without a solver.
- **Catalog downloads tell the truth.** The three tiers were a placebo: one
  dataset, stated once, with HYG's real depth.
- **Plate-solver verification cannot hang.** It is bounded by a deadline and
  reaps its child — an ASTAP GUI build opens a window instead of exiting on
  `--help` — and the CLI executable is preferred wherever both are installed.
- **Hot-plugged cameras appear without a restart.** A bus event now re-probes at
  roughly 3, 13 and 43 seconds. A single immediate probe cached "nothing here"
  while Windows was still installing the driver.

## Upgrading — please read

**Masters produced by 6.2.0 are void.** That release shipped a stacking
normalisation defect: a background-pair fit that erased stars, leaving 0.08% of
frame data. The fix follows PixInsight's default additive-with-scaling
normalisation, and v1 accumulating-master sidecars are refused by this build.

**Your captured frames are untouched.** Re-integrate them and the masters come
back correct.

The database moves to schema v59. The upgrade takes a backup first and applies
atomically, so a failed migration cannot brick your library.

## Known limitations

- **On-sky validation is owed.** Everything above was proven against simulators
  on Linux. The colour path has not run against a real plate-solved master with
  real APASS/HYG photometry.
- **Windows and Android runtime validation is owed.** Both binaries are built by
  CI and published here, but neither was installed or exercised for this
  release, and the Windows goldens were not re-captured.
- **The polar-alignment rotation fix has not run against a mount.** Three-point
  alignment now builds its rotation target in the mount's own frame — a target
  built from the *solved* coordinates made the mount absorb the very
  misalignment being measured, swinging toward the pole instead of stepping 10°
  in RA — and refuses a step that would cross the meridian. Reproduced from a
  live rig log and covered by unit tests, but not yet flown.
- **Two vendor connect-behaviour changes are untested on hardware**: Player One
  bin/ROI refusal and Atik undetermined-colour refusal.
- **SFTP password auth is deliberately absent** pending a dependency decision.
  Key auth is validated against a real OpenSSH server; Windows key-file ACL
  behaviour is untested, and a full disk on the server reports as a retryable
  transport failure because SFTP cannot distinguish it.
- The curves operation renders read-only in this build's editor.
- `denoise` on very large RGB masters has a high peak-memory profile.
- With no observing site configured, the default altitude trigger skips targets;
  the run outcome says so.
- Weather safety is fail-closed by default: with no weather device and an API
  that has never been fetched, an unattended rig will park.
