# Skotiq 6.2.0 — The Tightening Pass

## Summary

6.2.0 is a polish and correctness release. It changes several behaviors that
were accidents of implementation rather than decisions — most visibly around
what happens when a run stops — makes notifications and the event feed tell
the truth about what happened and why, and removes a large amount of dead code
that could never run in a shipped build.

## Autopilot and scheduling

- **Stopping an autopilot run now pauses the autopilot.** Pressing Stop on a
  scheduler-dispatched run used to leave the autopilot armed; it would
  re-dispatch the next target as though nothing had happened. Stop now pauses
  it and shows a visible "Autopilot paused — resume?" affordance. Safety
  aborts deliberately do NOT pause it: a passing cloud must not end an
  unattended night.
- **Removing a target from the scheduler removes it from the autopilot.** It
  used to remain eligible for automatic selection after you removed it.
- **Unpark only runs when the mount is actually parked.** The autopilot's
  UnparkNode used to issue an unpark unconditionally.
- **A failed interval autofocus no longer ends your night.** The trigger now
  restores the pre-sweep focuser position, logs a visible decision row,
  notifies your phone, and continues the run on the last good focus, deferring
  the next attempt a full cadence. Explicit autofocus nodes keep their
  configured failure actions.

## Notifications

- **Stop notifications only for stops you didn't cause.** The app used to push
  a "sequence stopped" notification to your phone even when you were the one
  who pressed the button. Your own stop is now silent; a stop from the
  scheduler, a rollback, or the disk watchdog pushes with its real cause named.
- A new "Autofocus Continued" notification category covers the
  continue-on-failure behavior above, so an unattended run tells you it kept
  going and why.

## Imaging

- **Stacked live masters save as FITS.** The live-stack master now writes a
  real FITS file with a synthesized EXPTIME (total integration) and DATE-OBS
  (first frame's timestamp); a master missing its timestamp is now a loud
  error instead of an empty header card.
- **Mosaic panel resume now restores panel state.** Resuming a mosaic used to
  look implemented while restoring nothing: the checkpoint sink was never
  wired into the production entry point, and a background checkpoint task
  erased wizard panel state. Both are fixed. Not yet validated on a rig; treat
  a mid-mosaic restart as supervised until it is.
- **The imaging screen's frame counter counts loop frames.** It used to count
  every frame the camera produced, including guide exposures, and it resets
  per loop.

## One press, one row, the real cause

The stop pipeline was rebuilt for accuracy end to end. A stop's origin —
operator, scheduler, rollback, disk watchdog — now travels from the button (or
the service) through the native executor to the event feed and the
notification router. The run's identity travels with the stop event, so the
feed can never attribute a stop to the wrong run. One press produces one
decision row: an operator stop is an unsilenceable manual-intervention
decision; system stops are system events with their origin named. Duplicate
stop and completion rows from event fan-out are folded away, and a new run
closes the fold so a stop can never absorb evidence from the run after it.

Related accuracy fixes: the camera tile reads "Exposing" during sequencer
exposures instead of "Idle", the dashboard's empty-state line reflects the
actual state, and the filmstrip names its session scope.

## Server

- **Suspended accounts can no longer log in.** Suspension used to end the
  current session but the login endpoint would still issue a fresh token.

## Removed

Nearly fourteen thousand lines of code that could never run in a shipped
configuration are deleted rather than left to rot: the Dart fallback device
clients (PHD2, Alpaca, ASCOM), an unimplemented alternative native backend, a
compile-flag mobile dashboard, and orphaned service paths. Dead code you cannot reach is
not a feature — it is a place for bugs to hide from tests.

For anyone building from source: a `.gitignore` pattern had been silently
excluding three production source files from the repository, so a fresh clone
of recent history did not compile. Fixed, and the tree audited for any other
source hidden the same way.

## What's verified

Every automated gate is green on Linux: the full Dart test suite across all
packages, the full Rust workspace, zero analyzer errors repo-wide, and the
format, placeholder, and behavioral audits.

**Not verified in this release:** this build has not itself been run against
real hardware or a real sky. The most recent real-hardware evidence is from
live sessions on 23 July and 9 August 2026, which exercised connect, capture,
guiding, and the headless path against a real ASCOM rig on earlier builds of
this line. The mosaic-resume and autofocus-continuation changes are exercised
by automated tests only. Windows artifacts are CI-built and archive-audited,
but the app was not launched on Windows for this release. See
`docs/known-limitations.md`.

## Downloads

| Platform | Artifact |
| --- | --- |
| Windows | `skotiq-6.2.0-windows-x64.zip` |
| Linux | `skotiq-6.2.0-linux-x64.tar.gz` |
| Android | `skotiq-6.2.0-android-arm64-v8a.apk`, `-armeabi-v7a.apk`, `-x86_64.apk` |

Android ships one APK per ABI; `arm64-v8a` is the right one for essentially
every current phone or tablet (the other two will refuse to install on most
devices). Every application artifact has a matching `.sha256` file.

Windows is unsigned and the Android APKs are signed with the project's own
certificate rather than an app store's, so install warnings appear. If a copy
of Skotiq from an earlier release is already installed, uninstall it
before installing this one — the signing identity changed with this release,
and Android refuses in-place updates across a signing change.
Vendor SDK binaries are not redistributed, so native device paths need vendor
support installed (ASCOM, Alpaca, INDI). The Linux archive targets an
ubuntu-22.04-class glibc floor with native dependencies bundled. There is no
macOS artifact.

## Upgrading

Back up your database directory first, then close any running copy. Replace
the bundle and launch once to confirm the version reads 6.2.0 and your library
and equipment profiles are present.

Nothing in 6.2.0 writes a schema an unmodified 6.1.0 cannot read; rolling back
is re-extracting the 6.1.0 archive.

## Breaking changes

None for users. For anyone building from source: the Dart fallback device
clients (`phd2_client.dart`, `alpaca_client.dart`, `ascom_client.dart`) and the
`SKOTIQ_COMPANION_UI` compile flag are removed.
