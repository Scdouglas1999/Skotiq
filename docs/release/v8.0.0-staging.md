Every artifact is flattened into `release-assets/` with `SKOTIQ-LICENSE.txt`,
`THIRD_PARTY_NOTICES.md`, `LGPL-2.1.txt`, `SOURCE-COMMIT.txt`; duplicate
manifest filenames fail the build.

## Prerequisites before `git tag`

1. **Version agreement** — desktop pubspec, mobile pubspec, `version.yaml`.
2. **Release notes file** — `docs/release/<tag>.md` must exist (workflow
   fails without it; it becomes the release body verbatim).
3. **Signing** —
   - OTA: `SKOTIQ_UPDATE_PRIVATE_KEY` + `SKOTIQ_UPDATE_PUBLIC_KEY` secrets.
     Without them manifests are unsigned and shipped updaters refuse every
     update (fail-closed, by design). Decide before publishing.
   - Android: `ANDROID_KEYSTORE_BASE64` (optional; absent → debug-signed beta
     APKs — for a stable release this decision matters).
   - Windows code signing: not configured; unsigned-binary SmartScreen warning
     is documented in the README.
4. **Update feed** — manifests' `downloadUrl` must equal the final GitHub
   release asset URLs (workflow derives these from the tag).
5. **Verification** — `dart run tool/verify_release_manifests.dart` runs in
   the publish job with `--require-signed` once the private key exists.
