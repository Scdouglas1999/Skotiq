# Skotiq 9.0.0

This release brings the desktop and linked clients onto shared run, device and capture state. It fixes problems across sequencing, camera control, mosaics and image reading, improves location and cloud forecasts, and removes several sources of delays during capture.

## Upgrade the host and linked clients together

Install 9.0.0 on the imaging host and every linked client. A version mismatch now identifies which side needs updating, and an older cached dashboard asks for an upgrade or reload. Automation without a version header remains supported through the authenticated API.

Back up your profile before upgrading. The database moves to schema 70, which preserves mosaic panel IDs, coordinates and captured-frame counts while adding traversal settings. Backup and restore were checked with an existing profile and an empty profile. To return to an older release, restore the backup rather than opening the upgraded database with an older app.

## Runs and equipment

Disabled steps and groups no longer take part in preflight checks. A refused meridian flip follows its recovery path without immediately issuing the same refused move again. Flat-wizard progress counts work actually completed and does not show a failed or interrupted attempt as complete.

Manual mount operations check the active guider, including paused and lost-lock states, before moving. If Skotiq cannot confirm the guider's state or stop it when required, the move remains refused. The scheduler and altitude checks retain learned horizon obstructions as well as the configured altitude floor.

A failed camera-capability read preserves the current gain or ISO and offset instead of replacing them with profile defaults. Failed reads of binning, motion, rotator, cooler and switch state remain errors or unknown values. Missing optional metadata stays unavailable.

Autofocus, guide-star and image-quality problems notify the operator; they do not become commands to pause, stop or park the run.

## Linked clients

The host's run records, equipment state, settings and capture metadata are shared by the desktop and companion screens. A viewing companion can disconnect while the host keeps imaging, and reconnect to the host's state.

Android no longer displays two notification permission prompts during the same startup after permission is declined. The disabled-notifications warning remains visible. Native voice-action links open the app without being sent to a nonexistent page, and actions that launch the app are queued before its engine starts.

## Location and weather

When the host has no saved observing site, it obtains an approximate internet-based location at startup. Saved sites and manual edits are preserved. Manual detection has a time limit and reports a usable error if it cannot find a location. Internet location is approximate; check the site before using it for planning or telescope operations.

Cloud forecasts use the National Weather Service's local forecast grid where it is available, with global providers as fallbacks. The weather readout, planner and current-cloud API use the same selection policy and show the source and valid time. Missing or expired forecast data no longer becomes a clear-sky value.

Satellite imagery is labeled separately from the numerical cloud forecast. Infrared brightness is not a cloud-cover percentage, and a forecast is not a local weather-safety sensor.

## Images, calibration and mosaics

Camera drivers and image processing use the same sensor-pattern and Bayer-offset definitions. Native FITS and XISF reading provides photometry cutouts in physical pixel units. Linked calibration uses the frame's full sky-coordinate information, including distortion and reference-pixel terms, and the matched stars' catalog magnitudes.

FITS text is written as printable ASCII. Refused calibration-master requests return a specific input error. Near-black frames produce a warning without interrupting capture.

If a libgphoto2 RAW download or decode fails, Skotiq retains the camera original. When that original is in temporary camera memory, further captures and automatic reconnections are refused so they cannot discard it. Retrieve the original, then explicitly disconnect and reconnect the camera.

Mosaic traversal settings survive saving, reopening and collaborative project use. Existing panel positions and captured-frame counts are preserved.

## Capture responsiveness

Histogram calculations and request-log writes no longer hold up the desktop's UI thread. Disk-space checks also start outside that thread, and duplicate exposure and save logging has been removed while the structured request records remain available. Weather-map tiles appear without an opacity animation.

On the measured Linux desktop, the final capture check completed 16 verified 26-megapixel FITS saves. Across 2,664 recorded frames, the longest measured frame span was 16.44 ms, with no traced main-thread system call taking more than 1 ms. This is a bounded simulator workload, not a guarantee for every screen or imaging night.

The 240 Hz display target is not met. The stock Linux Flutter engine schedules at about 60 Hz, and full-resolution image copies, weather rendering and some cold navigation still have measured costs. The [performance report](https://github.com/Scdouglas1999/Skotiq/blob/main/docs/release/performance-v9.0.0-linux.md) retains the results and remaining limits.

## Downloads and installation

Version 9.0.0, build 37, is a stable release. It includes a Windows x64 portable ZIP, Linux x64 tar.gz and ZIP packages, and Android APKs for arm64-v8a, armeabi-v7a and x86_64. Most current Android phones use arm64-v8a. macOS and iOS packages are not included.

The Linux package includes the LibRaw and JPEG libraries it needs and was checked in a clean Debian Bookworm environment. The Windows package includes its native bridge and updater. Vendor camera SDKs are not redistributed; native device support depends on the libraries and drivers installed on the host.

Android APKs use the existing release-signing identity, matching 8.2.1. All five OTA manifests are signed, and every package has a SHA-256 checksum. Windows executable Authenticode signing is separate and is not present, so Windows may display an installation warning.

## Validation

Affected regression suites passed 8,146 core tests, 1,459 desktop tests, 227 mobile tests and 249 remote-protocol tests. The app suite passed 5,482 tests with one skipped. Native tests, static analysis and the recorded release gates also passed; the [validation record](https://github.com/Scdouglas1999/Skotiq/blob/main/docs/release/validation-v9.0.0.md) identifies the tested revisions and exclusions.

All platform packages passed CI. Native Windows execution covered authentication, WebSocket communication, simulator capture and FITS readback. The downloaded Linux package was also driven on the desktop with networking and seven simulators. The signed Android app was checked in an Android 15 x86_64 emulator for startup, pairing, image display, reconnection and an update that retained its pairing.

This release has not had a physical rig night or interactive Windows testing. Android ARM packages were built and signature-checked, but their runtime was not tested on a physical phone. Previous rig-night results do not certify this refactor's on-sky behavior.
