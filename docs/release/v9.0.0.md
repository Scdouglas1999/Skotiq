# Skotiq 9.0.0 release candidate

Version 9.0.0, build 37, beta channel. This candidate is not published.

The refactor brings desktop and linked clients onto shared run records, device
state, settings, capture metadata, and error contracts. This release also
finishes the interrupted sequencer, mosaic, image-reading, and camera work.

## Upgrade together

The imaging host and every companion must run the same Skotiq release. A
version mismatch identifies which side needs updating. Older cached dashboards
receive an upgrade or reload message. Unversioned automation remains supported
through the documented API, subject to the normal authentication rules.

Back up the existing profile before upgrading. Schema 70 adds mosaic traversal
settings and infers the order of existing projects from their stored panels.
Panel IDs, coordinates, and captured-frame counts are preserved. Use the backup
to return to an older release; do not open an upgraded database with an older
binary.

## Run and device behavior

- Disabled sequence branches no longer participate in active preflight checks.
- A refused meridian flip follows its recovery path without immediately
  issuing the same refused move again.
- Flat-wizard progress reports work actually completed and does not show a
  failed or interrupted attempt as complete.
- A viewing companion can disconnect while its host continues imaging.
- Manual mount work checks active guider sessions, including lost-lock and
  paused states, before proceeding. A failed status check or failed stop
  leaves the move refused.
- Native scheduler and altitude-loop masks retain the site's learned
  obstructions as well as its configured altitude floor.
- A failed camera-capability read preserves the current gain/ISO and offset
  instead of applying profile defaults.
- Failed device reads no longer manufacture successful binning, motion,
  rotator, cooler, or switch values. Optional unavailable metadata stays
  unavailable.

Autofocus, guide-star, and image-quality problems notify the operator; they do
not become commands to pause, stop, or park the run.

## Images and mosaics

- Camera drivers and image processing share sensor-pattern and Bayer-offset
  definitions, with recorded driver sessions checking the conversions.
- Native FITS and XISF reading supplies photometry cutouts in physical pixel
  units. Linked calibration uses the frame's WCS, including CD/SIP and its
  reference pixel, and catalog magnitudes from the matched stars.
- FITS text is written as printable ASCII. Refused calibration-master requests
  return a specific input error instead of an unexplained server failure.
- Near-black frames produce a warning without interrupting capture.
- A failed libgphoto2 RAW download or decode retains the camera original.
  For captures stored in temporary camera memory, further captures and
  implicit reconnections are refused. Retrieve the original, then explicitly
  disconnect and reconnect the camera.
- Mosaic traversal settings survive save/load and collaborative project use.

## Validation status

The acceptance record is [refactor-readiness.md](refactor-readiness.md).
The [validation record](validation-v9.0.0.md) identifies tested commits and
local evidence. Earlier refactor and benchmark results do not certify this
candidate.

Windows runtime checks and an actual rig night remain outstanding: neither the
Windows laptop nor the telescope was available during preparation. Linux
simulator checks and Windows cross-compilation do not replace those checks.

The local Linux candidate targets Debian Bookworm-compatible x64 systems.
Appliance startup and healthchecks were verified with both supported archive
layouts. The Android APK is a debug-signed validation build; production signing
and a signed OTA manifest remain distribution work.
