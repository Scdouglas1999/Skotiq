# Skotiq 9.2.0

Update the imaging host to 9.2.0 first, then update each linked desktop or mobile client. Skotiq requires both ends of a Link connection to run the same release. The desktop and companion apps are build 40.

Most of this release is internal restructuring that makes the app easier to keep correct. The changes below are the ones you can see.

## During a night run

- When the camera drops, every frame of a run gets the camera retries and the session reopen. Before, only some frames did.
- A running sequence follows a camera that comes back under a new device id.
- A twilight wait that starts after it is already dark ends at once instead of waiting for the next day's twilight.
- After a meridian flip, centering uses your centering tolerance and corrects the same way the run's own recenters do. Guiding after the flip counts as locked the same way Start Guiding does. If the mount disconnects during a flip, Skotiq remembers where the flip stopped.
- Integration-time loops run all their passes on the timeline, and the disk-space check counts every pass.
- The progress card and the Activity tab count captured frames correctly.
- Critical run events always send a notification. A lost connection to the native engine is reported instead of failing silently.
- The dashboard keeps Stop available while guiding is settling, the guide star is lost, or PHD2 is calibrating.
- An unpark is no longer logged as a park.

## Connecting and reconnecting equipment

- A reconnect leaves equipment as it was. A mount that was tracking keeps tracking, and nothing moves when a device connects.
- Every connect runs a read-only check of what the device reports. The device card marks anything the check could not confirm.
- A warning from a driver no longer puts a working device into an error state.
- Filter wheel and focuser moves made from the app reopen the device after a USB drop. A safety monitor whose readings keep failing is reopened.
- Slew and center from the planetarium checks the camera and plate solver before moving the mount.

## Time and site

- An observing night starts at the site's own solar noon rather than the computer's local time. This matters when you image away from the computer's time zone and after midnight. The altitude chart, target suggestions, time estimates, the timeline, the dawn buttons and the twilight times all follow it.

## Calibration, DepthLock and Darkroom

- DepthLock reads Skotiq's own master darks.
- Library darks are matched on set-point and readout mode as well as temperature.
- Live auto-calibration uses the flat for each light's own filter. End-of-night calibration uses the lights from that observing night.
- Masters use one file-name style.
- Open in Darkroom from the live stack saves through the library, with a thumbnail.
- The Your Sky provenance trail shows real frame counts.

## Smart Night and planning

- Plans follow your saved wizard defaults and the profile's cooling set-point.
- Filters are found in the wheel by name.
- Plans built on a linked client check the host's darks.
- Tonight's suggestions work at high latitudes, and no exposure is shown as "0 s".

## Linked desktop, phone and web

- A linked client shows and controls the host's live stack.
- The pairing QR code names the computer and says whether it runs the full app or headless.
- Error messages read the same on the host and on clients.
- Pausing shows "Pausing: step finishing" until the current step has stopped.

## Smaller changes

- A GoTo asks "Slew?" once.
- The guide graph's SNR and star mass no longer drop to 0 on each guide step.
- Profile import and export behave like a normal save.
- The Weather Logger plugin is opt-in.
- Header titles fit in narrow windows.
- Logs from mobile startup and from the smaller packages reach the app log.
- A camera-memory capture the camera no longer holds leaves the retained list.

## Known issues

- Pause lets the current frame finish and save before the run pauses.
- Stopping a run by hand reports "Sequence cancelled" as an error.
- A linked client shows "No plan loaded" for a plan loaded through the REST API.
- The filter wheel, focuser and rotator do not yet follow a device that comes back under a new id.
