# Skotiq 9.3.1

Update the imaging host to 9.3.1 first, then update each linked desktop or mobile client. Skotiq requires both ends of a Link connection to run the same release. The desktop and companion apps are build 42.

This release fixes what a full simulated night turned up: a headless host running a real plan from dusk to dawn, driven from the Android app, with a meridian flip, a weather abort, a mount fault and a fresh install along the way. Most fixes help every client, not only phones.

## Guiding

- Built-in guider calibration could come out with the axes 134° or 57° apart instead of 90°. Each leg was a single short pulse, which moved the star about as much as the seeing does. Each leg now pulses until the star has clearly moved, measures the rate over the whole leg, and the guider locks on a fresh frame afterward.
- Every start of guiding picks its star from a fresh frame.
- A run arms its guiding triggers only for guiding it started, and its own mount moves (slews, flips, parks) stop the guider instead of reading as a lost star.
- A run that ran to its end no longer leaves "Guiding paused while the mount moves" on Tonight and Guiding afterward.
- The night log says why guiding stopped in one sentence, not "Guiding stopped" followed by a wire code.

## Mount safety

- Changing the site while the mount was parked could raise "dropped below the horizon" and send stop commands, because the mount's altitude changes with the site even though it never moved. The below-horizon rule now needs the mount to actually move.
- One mount fault was announced five times on Tonight. It now shows the mount guard banner with its actions, one toast, and the phone notification. The alarm still sounds.

## Runs

- Image tonight failed on any catalog suggestion from a linked client ("Value must be >= 1.0").
- Building a sequence for a second target scrambled the night: the new target took the plan's cool, unpark, park and dark steps ahead of its own slew, and left three disconnected steps behind. The new target now goes after the last one, adding it is one undo step, and the Sequencer opens on the Builder to show it.
- Run unattended was offered while a manual run was holding the rig. It is now blocked until that run ends.
- Tonight shows "Waiting for the meridian flip" while the run holds a frame for the flip.
- Mid-run edits on a linked client could revert about half a minute later after an undo.
- Plans built by Best tonight no longer pile up in the library under one name; each first save takes a free name ("NGC1313 Plan 2").
- The wheel's own filter names are used for a profile made on the phone, instead of "L" for every step.
- Dark and bias steps read by frame type ("Dark 55 s") in the Sequencer, Tonight's steps and the latest-frame pill, not by the filter in the wheel.
- After a run, Tonight lists what would block the next one, with its fix (for example, a disconnected camera with a Connect button).
- The finished run reads "Ended", and says how it ended ("Sequence stopped").
- The dark library check counts the plan's own dark steps only when there are enough of them.
- Exposure messages say "120 s exposures" and "90 s exposures, adjusted from 120 s for the sky". An exposure the sky did not change is no longer logged on every frame.
- Scheduler times are sent with their time zone, so a phone in another zone reads them right. Waiting messages give a date and time, and say why ("until dark at 21:40").
- The Lunar Terminator and Jupiter starter plans never dither, as they say.

## Frames

- Restoring a rejected frame moves it, and its thumbnail, back out of the reject folder.
- After the app reopens, the latest frame shows the settings the host recorded for it (a dark read as "L 55 s" before).
- Live view overlays (compass, scale bar) are off by default.

## Setup and connecting

- A setting for the ASTAP or astrometry.net path made over the API was acknowledged and ignored. It now takes effect.
- A missing capture folder says so before the run, on the phone too, with the reason. Error details from the host were dropped on the way to every linked client; they now arrive.
- GPS location stores the altitude as the site's elevation.
- A phone pairing over the home network without a code gets the control it asked for. Entering the address by hand pairs the same way as a found computer.
- When the imaging computer has forgotten the phone, the phone says so ("no longer knows this phone. Pair again.") with a Pair button, instead of "may be offline".
- Scan for devices in the profile editor says "Scanning…" and reopens the list with what it found.
- Connect all says each device's failure cause once.
- The host stops its network announcement when it stops; it used to leave it running.

## Phone and tablet

- The Ledger view works on phones, with columns dropped to fit. The overview gutter is gone.
- The autofocus and polar alignment pills sit just above the bottom bar instead of high on the screen, and an old autofocus result no longer reappears at every start.
- Sequencer side panels on a foldable or tablet open over the plan, one at a time. The phone has Undo and Redo, and tooltips no longer name keyboard shortcuts.
- The exposing pill keeps the time left at phone width.
- On a phone, closing the keyboard ends editing, and a dialog that opens over a text field does not bring the keyboard back when it closes.
- Built-in guider settings are on the Guiding tab.
- The Weather chip reads the safety monitor when weather monitoring is off.
- Several screens could fail to open after switching rigs (provider errors); those are fixed.

## Not tested

None of this has run on the rig. It was tested on an Android emulator against a headless Linux host with simulated equipment. The GPS path was tested with an injected location, not a real phone's receiver.
