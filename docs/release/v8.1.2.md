# Skotiq 8.1.2

Red is now the default accent for new installations. Existing color preferences stay as you set them.

This release brings the desktop and mobile interfaces onto a shared design system and fixes controls that could fall back to purple, including the dashboard exposure progress bar.

## Interface changes

- Image overlays retain your selected accent instead of switching back to the old purple palette. Red night mode remains red over images.
- Buttons, icon buttons, segmented controls, sliders, chips, radio buttons and progress indicators share their colors, shapes and interaction states. Selected, hovered and disabled controls behave consistently.
- Material dialogs and controls use the selected palette throughout, including background containers and secondary color roles.
- Desktop, mobile, the planetarium and updater use shared typography, corner radii and design tokens.
- Filter controls retain recognizable filter colors, with readable text in dark, light and red night modes. Scientific charts retain meaningful data colors.
- Custom accents in the light theme use readable foreground colors. Error indicators choose their foreground independently of the accent.

## Under the hood

A shared design foundation keeps the interface definitions in one place without introducing circular package dependencies. A new CI audit checks 1,433 UI files for hardcoded colors, fonts, radii and local slider styles so these inconsistencies are caught when code changes.

## Validation

Theme, control-state, image-overlay, settings and migration checks passed, along with portable desktop, mobile, planetarium and updater suites. Production static analysis reports no errors or warnings. The broader app run also encountered a host-dependent golden mismatch and a clock-sensitive ETA assertion; the unchanged ETA test passed on its own. Golden baselines were not replaced.
