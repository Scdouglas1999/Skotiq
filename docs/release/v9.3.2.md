# Skotiq 9.3.2

Update the imaging host to 9.3.2 first, then update each linked desktop or mobile client. Skotiq requires both ends of a Link connection to run the same release. The desktop and companion apps are build 43.

This release is a polish pass on the Android app, screen by screen, on a 360 dp phone during a simulated run. Most of it is about giving the screen to what you look at all night and keeping occasional controls small.

## Downloads

A release now carries one file per platform: the Windows zip, the Linux tar.gz and the Android arm64 APK, plus the update manifests and one SHA256SUMS.txt. The 32-bit Android (armeabi-v7a) and x86_64 APKs are gone. A phone running one of those builds finds no update for its architecture and says so.

## Tonight

- On a phone the header is one row: the run's state, the plan, and icon buttons for edit, start at dark, start, pause, skip and stop. It used to take a third of the screen. Stop still needs a hold.
- The HFR and star lines break across hours with no frames instead of drawing a line across the gap.
- "Slew completed" is no longer toasted for the run's own slews, or on Tonight at all.
- With no imaging computer linked, Tonight says to link one first instead of naming a missing device.

## Sequencer

- A phone keeps the Ledger view instead of dropping to compact cards at 360 dp. Columns drop to fit the width and the text size.
- A step's warning no longer cuts its properties off halfway down a phone; the editor fills the screen.
- With no run live, Start sits in the plan row and the pause, stop and skip row is gone. That row comes back while a run is live.
- The run's progress card is one line on a phone.
- A dark step's frames are captioned "Dark", not by the filter in the wheel. Calibration frames read "Dark", "Bias", "Dark flat" or "Flat Ha".
- Sky exposure advice shows on light steps only.
- On a phone held sideways, the add button no longer covers the properties pane's tabs.

## Guiding

- Settling, which follows every dither, shows in green like Guiding instead of the app's red. A pause shows in amber.
- On a phone the Guiding title no longer cuts to "G…": the "Not guiding" chip is left out while nothing is guiding.

## Linking and equipment

- A phone with no imaging computer linked says so on Equipment, with a Link button, instead of scanning and failing. The equipment setup wizard no longer opens on an unlinked phone.
- The alerts-off banner is one line on a phone, upright or sideways.
- In the link dialog on a phone, the address field gets its own row.
- On a live link, Reconnect now is no longer the status sheet's main button.
- The first-run device list stops above a phone's bottom bar instead of running past it.

## Demo rig (testing)

The phone app can simulate a camera, guide camera, mount, focuser, filter wheel, rotator, guider, weather station and safety monitor while it is not linked to an imaging computer. It is meant for testing and demos and is off by default: Settings > Replay & debug > Testing > Demo rig. A flask badge replaces the link dot while it runs.

Exposures, cooling, slews, focus, filters, guiding pulses and dithers work. Sequences, plate solving, stacking, autofocus runs and PHD2 report "Not available in the demo rig". Frames are marked "Not a real sky" and are deleted when the demo stops; their entries stay in the phone's frame list.

## Not tested

None of this has run on the rig. It was tested on an Android emulator against a headless Linux host with simulated equipment, at 360 and 411 dp, at 1.3x text size, and sideways. The demo rig ran only on the emulator.
