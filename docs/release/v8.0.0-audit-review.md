# 8.0 integration audit review

Runtime audit scope and failure policies are unchanged. The behavioral register
adds individual reviewed sites, with rationale for each. No file-wide exemption
was added. Rust test fixtures share runtime source directories, so the textual
auditors also report fixture defaults and cleanup.

The 17 new placeholder signatures were reviewed: five are test/harness code;
the Dither event permits no node identity; channel-combine defaults represent
absent optional constraints/roles; monitoring and recovery defaults format
optional diagnostic details; three moved trigger actions format missing error
messages; autofocus progress has no device identifier before admission; the
device-retry marker classifies an explicit unsupported error; exposure path and
quality-message defaults represent an empty parent directory or absent detail.

Actual issues corrected during this pass: DepthLock now logs a store-read error;
calibration planning refuses unknown gain/offset instead of requesting zero;
master building reports and excludes frames with unknown gain/offset; required
native master-result fields no longer silently decode as zeros. Migration,
version consistency, bridge boundaries and runtime fail-closed checks retain
their existing gates.
