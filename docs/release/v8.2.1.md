# Skotiq 8.2.1

This release fixes problems found during a rig night with a Windows imaging host and a linked Linux client. It improves meridian-flip recovery, run outcomes and the information shown on linked clients.

## Upgrade the host and linked clients together

Install 8.2.1 on both the imaging host and every linked client. The host now sends a `pier_changed` event when the mount reaches its new side during a flip. An 8.2.0 client incorrectly displays that event as “Meridian flip FAILED.”

The new host also provides night-history and ranked-target endpoints (`GET /api/runtime/night-history` and `GET /api/suggestions/ranked`). A new client falls back if an older host returns 404, but both sides should run 8.2.1 for the fixes in this release.

## Meridian flips and run outcomes

If a flip slew is accepted but the mount never moves, Skotiq backs the mount off its tracking limit and slews again. This addresses the behavior seen on the NYX when it stops tracking before the meridian.

A flip clears the old guide-star reference because the guide camera sees different stars on the new side. The guider restart checks signal-to-noise, and the luminance recovery retry now selects the correct filter-wheel slot instead of R.

Once the mount reaches the new side, a guiding, centering or refocus failure sends a warning and imaging continues. The run pauses for these quality problems only when “Stop the run for quality problems” is on. This changes the previous behavior, which paused the run after post-flip retries ran out. A flip that never reaches the other side still follows the configured flip-failure action.

A run that recovers from a flip error and reaches its plan’s end is now recorded as completed, allowing end-of-night darks to run. A failed run reports the latest error that was not recovered, rather than an earlier error that was already resolved.

The run message and Steps view follow each flip step and attempt, including the next retry time. The flip is counted when the mount reaches the new side. Afterward, neither host nor client offers another flip for that target, and the guiding stop reason no longer says it is waiting for the flip.

## Pointing, parking and guiding

Center no longer tries to solve through a filter slot named dark; it uses the plan’s next light filter. Slews unpark a parked mount, and evening light frames wait for dark.

Parking, or a guide-star search that finds no star, leaves PHD2 stopped instead of looping. The calibration card refreshes PHD2’s rates when guiding starts, stops or flips. A stuck ASCOM mount call no longer freezes requests to every other device.

## Linked clients

A client joining during or after a run now shows the host’s phase, plan rows, filmstrip, HFR, guide and focus charts, session counts and Log history. Ending the run keeps these views available. Imaging’s Session block and quick captures use the host’s frames, and Analytics opens on the host’s night.

The error banner shows the newest error and clears when the run resumes or the flip succeeds. A failed run is labeled Failed in red. Clients show the host’s run warnings, guiding stop reason and alert count. Guide RMS uses the Guide tab’s units, and device names match the host’s cards.

After the host has not answered for 10 seconds, the client marks the display as showing last-known values.

Plan ranks targets using the host’s catalog, optics, horizon and targets. Smart Night’s exposure context loads correctly, the false “optics are incomplete” warning is removed, and a plan closes on the client when the host no longer has it open.

The client’s Planetarium explains when its fallback sky is local and offers installation there. Settings → Annotations identifies settings saved on that computer. The startup log no longer asks a client to check a rig it never controlled.

## Other fixes

Idle focuser temperature is refreshed every 30 seconds, allowing idle temperature compensation to use current readings. Moon displays share one calculation, and the Plan header names the time for its quoted Moon illumination.

Frame counts agree across Tonight, Analytics and the pickers, using graded frames. Incomplete Sessions offers only tonight’s interrupted runs that captured frames.

Log entries describe fired triggers in plain words and name the filters when they change. The command palette lists the Flat wizard once.

## Validation

The fix wave passed 2,285 sequencer and bridge Rust tests on Linux, along with 7,605 core, 77 bridge and 1,373 desktop Dart tests. The app suite passed 5,154 tests; its framing-canvas golden has the same host-specific pixel difference seen in 8.2.0. Standard CI excludes host-specific goldens. Static analysis found no errors or warnings in core, bridge, app and desktop, and the behavioral audit passed.

Release preparation also passed workspace clippy with warnings denied, Rust and Dart formatting, production analysis, version consistency, placeholder, fail-closed, behavioral, dependency, bridge-boundary and UI-token gates.

Local simulator checks covered late joining, stale-host indicators, flip status and host-ranked targets. The fix-wave build was idle-checked on the Windows rig: devices reconnected, the mount stayed parked and cooling held its set point.

The meridian-flip fixes have unit and integration test coverage but have not been verified on the sky. This includes tracking-limit back-off, the post-flip guide-star check, the luminance retry, warnings after the pier change and flip counting.
