# Skotiq 6.0.0 — Make It Real / Collaborative Sky

Previous release: [v5.0.0 Living Sky](https://github.com/Scdouglas1999/Nightshade/releases/tag/v5.0.0) (2026-06-29). Packaged as 6.0.0+24. Operator overview: `docs/releases/v6.0.0-README.md`.

## Summary

6.0 is about leaving the rig running and trusting what it tells you afterwards. It builds on 5.0 (Your Sky, First Light, Constellation, master/slave, unified automation, S3 backup) rather than replacing any of it.

Two things carry the release. **Make It Real** is the reliability work: unattended Windows ASCOM that doesn't hang on COM apartment problems, headless auth that fails closed, weather and SafeRig that won't claim "safe" when they don't know, sequencer states that stay truthful while stopping, and signed-update machinery waiting on keys. **Collaborative Sky** is shared dark libraries, claimable mosaic panels, and live co-imaging sessions through your own hub, with consent and provenance attached.

This is still beta. Make It Real is covered by CI and by the July hardware run described below. Collaborative Sky and the larger remote and mobile surfaces have had much less time on real equipment. Where something is unproven, the notes say so.

## What's verified

This is the release's scoped capability statement. It appears word for word in the README and in `docs/known-limitations.md`; if those three ever disagree, the release candidate is not ready.

> Real-hardware validation for 6.0.0 was a Windows bench run between 22 and 26 July 2026 against an ASCOM Pegasus NYX-101 mount, a native ZWO ASI1600MM-Cool camera, and a ZWO EFW filter wheel, alongside a simulator instance. Camera connect, cooling, exposure, and image download are exercised on that hardware. **The mount was never commanded to move**, so slew, sync, park, unpark, homing, and meridian flip are unexercised on real equipment. **No frame was taken under a real sky** — the acquisition path is validated, the sky is not. The web dashboard and the Android companion were driven against a running host, but a second physical device on a real LAN with a firewall in the path was not tested. Fully-unattended **headless** acquisition and a full-night soak are **not** verified and must be supervised. **Linux** is early testing; **macOS** and **iOS** are unbuilt, untested, and ship no artifact. Every other device path — switches, domes, covers, and the remaining vendor SDKs — is **capability-gated**: present in the app, but not a support guarantee until it is verified on your rig.

The full account of that hardware run, including what it did not cover, is under [Hardware validation](#hardware-validation) below.

## Collaborative Sky

Constellation already let several rigs contribute atlas tiles to a self-hosted hub. Collaborative Sky turns that into coordinated work for clubs and multi-rig sites.

**Shared calibration libraries.** Match remote dark masters against a light-frame context, accept them (which downloads into your local library), publish with a consent and license, or retract. Provenance travels with the master: `shared_by`, `shared_at`, `license`, `provenance_json`. Darks are the safe share, keyed on sensor, gain, offset, binning, exposure and temperature. Flats stay optics-train specific and the matcher refuses cross-train reuse.

**Distributed mosaics.** Publish a `MosaicProject` and let contributors claim panels with a baton, which prevents two rigs collecting the same panel. Stalled claims can be force-released. Panel masters upload to the hub, which assembles the output. A twenty-panel project no longer needs twenty clear nights on one mount.

**Live co-imaging.** Create or join a session on a shared target, contribute subs, and assign framing offsets so contributing rigs don't stack identical fixed-pattern noise. A longitude baton hands off as darkness moves east. Consent gates fail closed.

The UI for all of this sits under Plan Tonight → Discover.

Schema moves to v56, additively, adding collaborative columns and `co_imaging_sessions`. The migration is tested, but back up first.

Deployment is unchanged from Constellation: self-hosted hub only. There is no public default hub and no account service. Earlier scaffolding for a default hub was removed deliberately.

## Headless services

The appliance and `--headless` path picked up the pieces that make walking away practical.

Startup auto-connect uses the same `autoConnectOnStartup` setting as the GUI and refuses to drive a non-local backend. It fail-softs: a dead camera or a backend that isn't ready logs loudly and leaves the API up so you can recover remotely, instead of crash-looping the daemon.

Shutdown is bounded. SIGINT and SIGTERM safe the rig first, then tear down mDNS, relay, HTTP, OTA, auto-save and providers with a timeout on each step. A second Ctrl+C forces exit and a hard deadline backstops the whole thing. Previously a hung `stop()` could wedge the process until SIGKILL.

The disk-space watchdog arms itself against the configured capture path without anyone clicking "Start watchdog", and blocking severity stops the sequencer with a logged reason.

## Plan Tonight and Unattended Autopilot

Both share the scoring, horizon, darkness and safety contracts from the 5.0 automation core. What 6.0 clarifies is ownership. Plan Tonight is the manual surface. Unattended Autopilot shows a read-only preview of what the live scheduler would slew to next, under the same constraints as the real engine. When autopilot takes the editor slot it stashes unsaved manual work rather than discarding it, and disengaging gives the sequence back.

## Headless API

The route catalog grew substantially, into the mid-500s depending on branch tip. The additions worth knowing about:

| Area | Examples |
| --- | --- |
| Collaborative Sky | `/api/coimaging/sessions…`, `/api/mosaic/collaborative…`, calibration accept/publish/retract |
| Sequencer | `POST /api/sequencer/load-and-start`, Smart Night settings, scheduler state and control, predictive focus-model routes |
| Calibration and science | dark-library create-master and clean-orphans, defect-map apply, post-session settings, transient state, notes CRUD |
| Equipment and safety | rotator reverse, meridian-flip settings, Home Assistant settings, `POST /api/safety/cancel-acknowledgement` |

`load-and-start` lets a remote client hydrate and start a saved sequence on the host, so the web dashboard no longer has to synthesize native sequence JSON in the browser.

## Desktop

Dashboard moved toward the cockpit layout with Session Vitals, Sky Context and opt-in Forensics. Planetarium picked up omnibox, fly-to and atlas performance work. SkotiqIcons, Hanken Grotesk and Spline Sans Mono now cover more surfaces. Mosaic project UX, frame-grading eccentricity gates, flat-wizard merge and authority-aware save paths, and remote-aware analytics all landed.

Your Sky, First Light and Constellation are unchanged from 5.0. 6.0 hardens remote authority around them, so slave-blind Living Sky routes fail loudly instead of returning empty local state on a tablet.

## Imaging pipeline

Per-sub noise now reaches the qualities map, and drizzle gets the same resolved calibration as the stack path. Filename pattern variables follow FITS `DATE-OBS` correctly, where `$DATE` could previously land a day behind local ISO; a typo in a variable now fails loudly instead of silently falling back. The `_cal.fits` suffix is recognised consistently across imaging badges and services. Centering and plate-solve failures fail closed. The autofocus overlay reports malformed progress as an error rather than sitting on a stuck "running" UI.

## Equipment

Mount, focuser and rotator cards got tighter range checks. Switch control and switch-channel services log fail-closed on shutdown races. Mount park fails closed when a driver refuses `canPark`, so there is no dead button that hits "Not implemented". A focuser command treats an equipment profile as connection intent, not live move authority while disconnected. Camera temperature polling aligns with the mobile cooling-resume fix.

## Mobile

The Science tab exports the host PDF instead of synthesizing one from a local DAO the phone doesn't have. Camera cooling resume cancels warm-up and restores the configured target, single-flight. Mount park and settings toggles are single-flight across rapid taps. The dashboard stays gated while first-run detection is still loading. The QR scanner offers an in-place retry when permission is denied. Session picker pagination stopped duplicating overlapping pages. Push re-pair and server switching no longer leave registration aimed at the previous host. Live activity, voice control and watch complication providers handle dispose and rebind on connection changes.

Android release keystore wiring is present, though the secrets are owner-gated, so without them the debug-sign path stands.

## Web dashboard

Gallery and preview images use authenticated blob fetches with an Authorization header, never a token in the query string, and the server rejects bearer tokens in general query strings. Sequencer load-and-start posts `{ sequenceId }` to the host. The dome sync body key is `enable`, not `enabled`, for both states, and that is contract-tested.

## Windows ASCOM STA worker

ASCOM COM objects need a single-threaded apartment. The desktop GUI provides a Windows message pump; headless provided neither. That one gap caused most of the unattended Windows failures operators reported:

| Issue | Symptom | Cause |
| --- | --- | --- |
| B1 | Connect opens a modal driver dialog and hangs forever | STA with no pump to dismiss the dialog |
| B2 | Mount won't connect headless | `CoCreateInstance` hangs on a pumpless STA thread |
| B5 | Filter-wheel set looks like it worked but didn't | property-put from a non-owning thread |
| B18 | Camera works, then `StartExposure` fails until reconnect | heartbeat and lifecycle off the STA owner |
| B19 | Loaded sequence cancels itself about 1.5s after start | mount-tracking baseline armed before the mount was tracking |

A single persistent STA worker now owns `CoInitializeEx(STA)`, runs a message-only window pump, and executes every COM operation for all ten device wrappers through a channel. Headless dialog suppression plus a watchdog on a separate thread force-close modal windows when `CoCreateInstance` blocks. B19 also gets a lazy mount-tracking baseline and scenario-sim coverage.

The `cfg(windows)` path is syntax and format checked in CI. Real ASCOM hardware was exercised in the July validation run below, but not across a full unattended night. For a night that matters, the supervised desktop path is still the safer choice.

## Sequencer lifecycle

The executor now publishes states that stay truthful while it tears down:

| State | Meaning |
| --- | --- |
| `finalizing` | stop and cleanup in flight, busy, not terminal |
| `stopFailed` | native stop unconfirmed, so Stop stays retryable and Start stays blocked |
| `cleanupFailed` | stop confirmed but persistence or end-session failed, identity retained so Stop can retry without losing the run |

These replace the old "looks idle but isn't" and "looks failed but Start behaves oddly" states after a bad stop on a flaky host. Skip-while-paused capability drift is fixed, as is swipe-delete and Undo corrupting the mobile sequence editor tree.

## SafeRig

Park, dome, cover and pause each have clearer ownership now. Optional steps (abort exposure, quiesce secondary capture, disable cooler) are gated so a weather pause and a terminal shutdown do different, correct things. An idle or already-paused sequencer isn't sent a spurious pause, and an already-parked or disconnected mount skips park cleanly. Per-step failures are keyed individually instead of collapsing into one opaque failure.

On terminal shutdown the live exposure aborts before the mount parks, so the mount doesn't move under an integrating sensor. Weather safing can leave cooling on so a resumed run stays cold.

## Weather

No weather data means UNSAFE, and the executor is told, so a disabled toggle can't assert SAFE and suppress a real hazard. Verdict push is host-authoritative and slaves mirror fail-closed rather than inventing local truth. Snoozed and abstain paths don't claim SAFE to the Rust `WeatherUnsafe` trigger. Open-Meteo hourly cloud parsing is guarded against the regression that produced a silent empty forecast, which reads as clear sky. Safety acknowledgement cancel is remotely reachable.

INDI weather and switch parity still needs checking on real Linux and macOS observatory stacks before you rely on it for unattended safety.

## Remote authority

Most of the remote work is about making sure the UI talks to the host it thinks it's talking to. A host switch cancels in-flight remote work (scheduler rows, planner dialogs, captured images, thumbnails, guider stars, remote settings) so one host's payload can't land on another. Authority-bound dialogs close when the backend swaps, so you can't confirm a destructive action against the previous rig. Profile default and sort order round-trip, so a slave polling status can't thrash the host's default profile. Focus-model answers on a slave match the host's in-run decision. Non-idempotent hardware POSTs (slew, relative focus move, exposure) remain single-attempt, which companions rely on.

## Security

**Headless auth now fails closed.** Earlier builds served the API open when no token was configured. Now, with no token and no opt-in, privileged routes return 401. Pairing, discovery and the static dashboard stay reachable so a fresh appliance can be bootstrapped. Serving open requires `--allow-unauthenticated`, and exposing that to the LAN additionally requires `--allow-unauthenticated-lan`. Two keys, deliberately. Malformed auth specs fail closed at launch rather than partially opening.

Fine-grained scopes map routes to resources (`camera`, `mount`, `sequencer`, `mosaic`, `coimaging`, `constellation`, `system`) with view, control and admin actions. Legacy coarse tokens still work. Collaborative mosaic, co-imaging and constellation routes no longer fall through to `system`, so a `system` grant stops silently unlocking club collaboration surfaces.

See `docs/headless-secure-setup.md`. Bind narrowly, and don't use unauthenticated LAN for normal imaging.

**Consent and provenance.** Publish and share paths require explicit consent and a license, private defaults fail closed, provenance travels with shared masters, and rate limits cover the collaborative mutating endpoints.

**Updates.** On top of the Ed25519 updater contract from 5.0: vendor-signed `releaseDate` must move forward per channel, so older or implausibly future manifests are refused, and the high-water mark only advances after a fully verified stage. A corrupted anti-freeze store no longer fail-opens into accepting anything. Key rotation and revocation are supported in the verifier. The release workflow wires update-manifest signing, Windows Authenticode and the Android release keystore, each of which no-ops safely when its secret is absent: the build succeeds, the artifact stays unsigned, OTA stays refuse-all. Headless logs clearly when OTA is refuse-all, so an inert updater isn't mistaken for a working one.

Until keys, certs and a server are provisioned, official builds are manual-update and unsigned in practice. See `docs/release-signing.md`.

## Hardware validation

Between 22 and 26 July the release was driven against a real rig: a Windows host with an ASCOM Pegasus NYX-101 mount, a native ZWO ASI1600MM-Cool and a ZWO EFW, alongside a simulator instance and a live GUI harness. About sixty defects came out of it. All of them were seen on running software rather than inferred from reading code, and each fix was checked by repeating the observation that found it.

The mount was never commanded to move. It stayed parked and not tracking throughout.

Most of what turned up was the software reporting something that wasn't true:

- Requesting an out-of-range gain reported back the value you asked for, while the SDK had quietly clamped it. The false number went into the FITS `GAIN` keyword and the image database, so a dark library keyed on it could never match.
- Device capabilities served cooler state, filter position and safety status from a five-minute cache. The cooler read `false` for 259 seconds while it was running.
- Out-of-bounds subframes were relocated silently and reported as success, so you got a different part of the sensor than you asked for.
- On an untargeted run the save-path template aborted the exposure after the shutter had already opened, throwing away real photons and finishing with zero frames.
- Analytics reported 0.0133 hours of total integration where the frames on disk came to 0.1039.
- Thirteen runs showed as "running" while the sequencer reported idle. Runs killed by a crash were never reconciled.
- The dashboard said darkness was 21 hours away while the sun was 30.6° below the horizon.
- Both weather endpoints returned HTTP 500 on a clear night, because the sentinel for "no cloud front" is infinite and has no JSON encoding. The answer failed exactly when it was good news.
- Nineteen of the thirty-six backend error variants leaked their Dart constructor form into user-facing text, so operators could be shown `SkotiqError.noImageAvailable()`.
- Stop and abort endpoints reported success when nothing had been running.

Several reliability problems only appeared under load. An unattended run could deadlock indefinitely on a rig with no focuser: a filter change invalidated autofocus state, an always-armed trigger fired, and the run paused with no terminal event, reporting `running, 0%` for 148 seconds with no frames. Stop could hang forever, because the wait for a terminal confirmation was unbounded and the bridge legitimately drops events when its receiver lags, leaving the run in `stopping` all night with nothing logged. Automatic recovery could issue `set tracking = true` on a parked mount, from a failure that had nothing to do with the mount. One trigger re-fired roughly 28,000 times a night, writing a log row each time. And a successful re-pair didn't clear the bearer-token lockout, so after a restart a paired tablet could trip the limiter with its stale token and stay locked out while holding a valid new one.

A sweep across nine window sizes and the large font setting found the settings pane, sequencer toolbar, dashboard tiles and polar alignment panel overflowing at 1024×768 and below. In one case the folder-browse button was clipped off screen, which was the only way to change those paths. All fixed and re-checked at every size.

What this run did not cover:

- **No imaging under a real sky.** A frame was captured through the optics at the parked pointing, but it had no stars in it; the scope was capped or enclosed. The acquisition and retrieval path is validated on real hardware. The sky is not.
- No mount motion at all, so slew, sync, park, unpark, homing and meridian flip are unexercised against this hardware.
- No switch device exists on either test machine, and the simulator doesn't implement one, so that capability path is unverified.
- macOS and iOS remain unbuilt and untested.
- Long unattended soak across a full night, second-device LAN and firewall smoke, live S3/MinIO/B2 restore, and production signing evidence are all still outstanding.

## Breaking changes

Read this if you automate against the headless API or relied on it being open by default.

| Change | What to do |
| --- | --- |
| Headless without a token 401s privileged routes | Issue a token (`--auth-token`, `SKOTIQ_AUTH_TOKEN`, or pairing), or start with `--allow-unauthenticated` if you accept the risk. LAN open also needs `--allow-unauthenticated-lan`. |
| Collaborative resources are separately scoped | A token holding only `system` no longer unlocks `/api/mosaic/collaborative/*`, `/api/coimaging/*` or constellation collaborative routes. Grant `mosaic`, `coimaging` or `constellation`. Coarse `admin` and `control` still work. |
| Dome sync body key is `enable` | Update clients posting `/api/dome/sync`. |
| Backup `customPath` rejected | Restore by backup `id`. |
| Sequence children route needs `parentNodeId` | Include it. |
| Mock push needs `mock: true` | Set it explicitly, or mocks won't run. |
| Autopilot no longer overwrites unsaved manual sequences | Save or discard manual edits first. |
| Schema v56 | Additive. Back up before upgrading. v55→v56 migration is tested. |
| OTA | Refuse-all and unsigned until keys are provisioned. Don't assume auto-update works because an updater binary is present. |

Upgrading from 5.0.0 preserves configuration and profiles, and the Living Sky tables from v52–v55 stay as they are.
